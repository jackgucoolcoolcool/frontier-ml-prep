Act I · The problem

Vision in 2026 is still a specialist zoo

Segmentation

SAM 3, Mask2Former lineage — promptable masks, but a dedicated architecture, dedicated training, mostly closed task format.

Geometry

Generation

Frontier T2I/editing models — trained on web-scale pixels, but treated as a separate species from perception models.

The structural question LLMs unified NLP because every task is expressible in one output space: text. What is the output space that unifies vision — and which pretrained prior do you inherit when you pick it?

Every specialist re-learns the same visual world from scratch. Our claim: the rightmost box already existed — it was called an image generator.

Act II · Encoding 1/4

Semantic segmentation — colors as class logits

Prompt carries the label space: “Generate a semantic segmentation visualization using this color mapping: {sky: (70,130,180), road: (128,64,128), …}” — as prose, JSON, hex, or RGB tuples. Because classes are named per prompt, the vocabulary is open: any noun phrase can be a class.

Decoding is nearest-color assignment per generated pixel $\hat{p}\in[0,255]^3$:

$$ k^{*} \;=\; \arg\min_{k}\; \lVert \hat{p} - c_k \rVert_2 $$

The generator never emits exact colors (VAE compression, anti-aliasing, sampling noise) — but decoding is still exact as long as color error stays under half the inter-class distance.

The quiet design rule

Choosing well-separated colors in the prompt is part of the method. The color mapping is an error-correcting code; class colors are codewords, and the margin between them is your noise budget.

What you get for free

  • Open vocabulary — no fixed class list anywhere
  • Sharp boundaries — the generator already knows how to draw edges
  • Human-inspectable outputs — failures are visible

Act II · Encoding 2/4

Instance segmentation — the model invents the palette

Instance count is unknown a priori, so the prompt just says “color each <class> instance differently.” The model picks arbitrary distinct colors; a five-stage decoder (paper Appendix A) recovers the instances:

  • 1

    Background removal — pixels within color tolerance $\tau=14$ of the declared background color are dropped.

  • 2

    Seeded floodfill — 16-connectivity, color-similarity threshold $\tau^2$, grows instance components.

  • 3

    Noise pruning — components < 0.02% of image area discarded (anti-aliasing slivers).

  • 4

    Boundary cleanup — $3{\times}3$ binary erosion, threshold $\theta_{\text{erosion}}=0.1$.

  • 5

    Fragment merging — same-color components whose bboxes (expanded $\gamma=5\times$) overlap are merged — rejoins occlusion-split instances.

Where the elegance leaks The “no task-specific components” story is true of the weights — but five hand-tuned hyperparameters ($\tau$, area cutoff, $\theta$, $\gamma$, connectivity) now live in post-processing. Deterministic and cheap, yes. Free, no.

Failure modes

  • Two instances get near-identical colors → they merge (color choice is uncontrolled model behavior)
  • Erosion + pruning shrink masks — they come out “slightly smaller and finer” than GT (we say so in the paper)
  • $\gamma$-merge can fuse distinct same-colored far-apart instances
  • VAE color drift silently eats the $\tau$ budget
Fix I’d propose Constrain the palette in the prompt — maximally-separated colors from a fixed list, assigned left-to-right. Turns an open color-assignment problem into a decodable code, and makes instance identity a protocol instead of a hope.
9:30 – 11:30. This is the honesty slide — own the decoder before anyone asks. The pitch: the decoder is task-generic in spirit (color → set structure) but its five constants were tuned against these benchmarks, so some fraction of the score lives outside the network. My palette-protocol fix doubles as a “what would you do” answer.

Act II · Encoding 3/4

Metric depth I — squashing $[0,\infty)$ into a code

Depth is unbounded; RGB is a bounded cube. Stage 1 squashes depth with a power transform (Barron 2025), $\lambda=-3,\; c=10/3$:

$$ t \;=\; 1-\Big(1-\tfrac{d}{\lambda c}\Big)^{\lambda+1} \;\;\xrightarrow{\;\lambda=-3,\,c=10/3\;}\;\; t = 1-\Big(1+\tfrac{d}{10}\Big)^{-2} $$
$$ d \;=\; 10\big((1-t)^{-1/2}-1\big), \qquad \frac{dt}{dd} \;=\; 0.2\,\Big(1+\tfrac{d}{10}\Big)^{-3} $$

Strictly monotone, $t(0)=0$, $t(\infty)=1$, closed-form inverse. The derivative is the design decision: resolution is spent densely on near depth.

Why not linear or log? Linear needs a hard $d_{\max}$ and wastes range on the far field; log is unbounded at both ends. The power family interpolates between them — matching how metric-depth metrics ($\delta_1$, AbsRel) price relative error, with the knee (~10 m) set as a prior on where photos live.
d < 4.1 m
gets half of the entire code range — $10(\sqrt{2}-1)$ m. Relative precision stays roughly constant with distance.
11:30 – 13:30. Slow down — this is the deepest technical content. Talking track: (1) requirements — bijective, closed-form inverse, resolution allocated where the metric prices it; (2) the derivative falls as (1+d/10)⁻³, so half the code range covers under ~4 m; (3) the constants encode a prior about photographs. If asked “why not disparity 1/(1+d)?” — workable but a fixed decay shape; the power transform is the tunable family containing it.
Act II · Encoding 3/4 (cont.)

Metric depth II — a rainbow path is worth 2.8 extra bits

Stage 2: route $t$ along a piecewise-linear path through the RGB cube — black→red→yellow→green→cyan→blue→violet→white. Decoding projects each generated pixel onto the nearest path segment, reads $\hat t$ from arc length, and inverts the squash → meters.

Strip is linear in $t$ (the code); ticks are meters (the world). 0–5 m eats half the palette; 20 m–∞ is squeezed into the right tail. The asymmetry is the design.

Precision

Grayscale = 256 levels. A 7-edge path ≈ $7\times255\approx1785$ levels ≈ 10.8 bits — 2.8 extra bits from the same pixels.

In-distribution

Web pretraining is full of false-color scientific viz — “render a rainbow depth map” is a style the generator knows. Smooth grayscale ramps are exactly what VAEs band.

Noise robustness

Decoding projects a 3-vector onto a 1-D path — generation noise orthogonal to the path is discarded. Plus colormap augmentation (Plasma/Inferno/Viridis/gray) teaches the concept, not one palette.

13:30 – 15:00. Three independent reasons the rainbow beats grayscale — precision, distribution match, noise geometry — make sure all three land. The colormap-augmentation point is the LLM analogy: instruction diversity forces binding the concept “encode depth in the stated code,” same reason prompt diversity matters in instruction tuning.

Act II · Encoding 4/4

Normals, and language doing the task selection

Surface normals — direct linear code

Camera-space unit normal $\mathbf{n}=(x,y,z)\in[-1,1]^3$ maps linearly to channels:

$$ R=\tfrac{1-x}{2},\qquad G=\tfrac{1+y}{2},\qquad B=\tfrac{1+z}{2} $$

The standard normal-map convention (the $x$ sign flip is a handedness choice — all that matters is encode/decode agreement). Decoding inverts the affine map and re-normalizes to unit length — which projects out most per-channel generation noise.

Act II · Training

The recipe — striking for what it doesn’t contain

BaseNano Banana Pro — architecture, size, and objective stay undisclosed (proprietary); publicly: “a frontier image generation/editing model.”
MethodInstruction tuning only. No architecture change, no task heads, no auxiliary losses, no learned decoders.
MixtureVision-task data mixed into NBP’s original training mixture at a “very low ratio” (undisclosed). The replay of original data is what preserves generation — same recipe as LLM continued-pretraining.
2D labelsPseudo-labels from in-house models on web-crawled images — no human dense annotation at scale.
3D labelsSynthetic renders only. Zero real-world depth/normal data; no camera intrinsics at train or test time.
HygieneNo training data drawn from the evaluation benchmarks.
Why the low ratio works Format-teaching is gradient-cheap: the tasks reuse existing features, so few consistent gradients suffice. A high ratio would drag the whole model toward flat-color “visualization style” outputs. Replay keeps the gradient distribution near pretraining → catastrophic forgetting suppressed.
17:00 – 18:15. Read the table as a list of absences: no new losses, no human labels, no real 3D data, no intrinsics. Each absence transfers credit from the tuning to the pretrained prior. The synthetic-only 3D row is the setup for the next slide — the single most striking result.
Act II → III · The striking result

Metric meters from a model that never saw real depth

Formally ill-posed: scale the scene by $s$ and the focal length by $s$ — the projection is invariant. Absolute depth without intrinsics shouldn’t be possible.

Unless you have priors. The model must jointly infer implicit intrinsics + scale from content: known object sizes (people, cars, doors), ground-plane and horizon geometry, perspective-gradient statistics — and the strong empirical prior that web photos come from a narrow $(\text{camera},\text{scene})$ distribution.

$$ p(d \mid \text{image}) \text{ concentrates because } p(\text{camera},\text{scene}) \text{ does} $$
The kicker Depth tuning used synthetic renders only. So the real-world scale prior cannot come from the depth data — it must come from generative pretraining. This is the single strongest piece of evidence for our thesis.

Breaks exactly where the prior breaks

  • Telephoto compression, macro (focal length far from modal)
  • Scale-free content — rocks, clouds, textures
  • Miniatures / tilt-shift — adversarial to the prior by construction
  • Fisheye and unusual optics
18:15 – 19:45. Best moment of the talk — take it slowly. Structure: impossible in principle → possible with a Bayesian prior over (camera, scene) → and the prior can only have come from generative pretraining because the tuning data was synthetic. The failure modes aren’t bugs; they’re the prior’s support boundary, which is exactly what the theory predicts.

Act IV · Mechanism

Why would generation pretraining yield perception?

The argument Generation strictly requires implicit perception. To render consistent occlusion, shadows, contact points, and object scale, the model must internally compute segmentation-like grouping, depth ordering, and surface orientation. Perception tasks just read out what generation had to compute anyway.

The evidence chain escalates the claim: from “generative features help perception” (DIFT) to “a light finetune makes a generator a specialist” (Marigold) to “the generator is a generalist vision model, one output-format lesson away” (Vision Banana).

22:10 – 23:30. Walk the timeline; each hop raises the claim’s strength. Then bridge to the LIMA framing: tiny format-teaching data + no new losses + SOTA ⇒ the capability pre-existed; tuning aligned the output format. That’s the superficial-alignment hypothesis, vision edition: pretraining is where knowledge lives, post-training is where interfaces live.
Act IV · Epistemics

What our results do — and don’t — establish

1 · The claim is checkpoint-level

NBP’s pretraining mixture is proprietary and Gemini-lineage — it is not a pixels-only diet. So the claim we can defend is:

“A frontier generator checkpoint contains generalist perception, extractable with light tuning.”

— and not “pixels-only generative pretraining suffices.” Separating those two claims takes a pretraining-attribution ablation we have not run yet.

2 · No FLOP-matched baseline

We did not compare against a specialist trained with generator-scale compute. So far the win is an intercept win (a huge pretrained prior amortized across tasks), not a proven slope win (better per marginal FLOP).

“Generalist beats specialist per FLOP” remains an open, testable claim — arguably the missing experiment of the unification debate.

Why say this unprompted Naming the edges of our own claim before the audience does is the point of this slide — it shows the claim was engineered, not marketed, and it tees up exactly the experiments on the next slide.
23:30 – 25:00. The research-taste centerpiece — coming from an author, raising both limits unprompted lands even stronger. Practice the intercept/slope distinction cleanly: intercept = free capability from an existing prior; slope = per-FLOP efficiency of the unified objective, which nobody has measured. Precision about what we actually showed is the note to hit.

Act IV · Limits

Where the RGB interface genuinely ends

No abstain

SA-Co scores negative queries: asked for an absent class, output nothing. Pixel space has no null token — the model hallucinates plausible masks and needs a Gemini pre-filter (“is X present?”) to gate generation. Rejection is bolted on outside the model.

No confidence

No logits ⇒ no native calibration. Options: sample $K$ answer-images and use agreement (principled, $K\times$ cost — self-consistency for vision); decode-distance to the nearest legal code (cheap proxy); or distill into a specialist with real logits.

Cost & sparsity

One prediction = one full frontier-model generation — orders of magnitude beyond a SAM forward pass; we have not published latency numbers. And sparse outputs (boxes, keypoints) waste the interface; video tracking needs cross-frame color persistence the generator doesn’t guarantee.

The rule to carry away The interface excels exactly when the output is a dense field over pixels. The sparser and more structured the output, the more it belongs in tokens. (Flow fits — the Middlebury color wheel is already a near-invertible code. Boxes don’t.)
26:00 – 27:15. Contrast with token-based unifiers: they can emit an “empty” token and expose logprobs — abstention and confidence are native. That’s the genuine open edge of output-space unification, not the precision ceiling everyone assumes (which slide 13 killed). Deployment reality in one line: the pattern that ships is generalist-as-teacher — mint pseudo-labels, distill small specialists; the same relationship frontier LLMs have to production classifiers.

Act V · Research program

Pixels and latents are two poles of one axis

Vision Banana — unify in pixel space

  • Interpretable, human-inspectable outputs
  • Maximal reuse of the generative prior
  • Precision capped by 8-bit × VAE (fine in practice)
  • Pays full generation cost per prediction

The latent-space pole — predict in frozen SSL latents (JEPA-style)

  • Targets live in a frozen self-supervised space (DINO / JEPA), not pixels
  • Cheap, information-dense targets; collapse-proof (frozen)
  • Trades away native synthesis; needs decoders/probes to read out
  • Bets dense capability doesn’t require paying for pixels
The experiment nobody has run The scaling law of emergent perception. Perception readout quality vs generator pretraining compute — and does the tuning-data requirement shrink with scale? If capability truly pre-exists, the format lesson should get cheaper as the generator grows. One curve would tell us whether generative pretraining is vision’s substrate — and which pole of the axis wins per FLOP. Pairs with the FLOP-matched 4-arm grid (generalist vs specialist × pixel vs latent).

Illustrative sketch only — no such measurement exists. The hypothesis: the readout curve crosses the FLOP-matched specialist line, and the crossing point is where “train a generator, then ask” becomes the dominant strategy.

27:20 – 29:00. Be fluent on both poles: Vision Banana maximizes prior reuse at inference cost; the latent-space pole minimizes inference cost, betting the capability can be read out in representation space. The proposed curve — perception quality vs generator compute, with tuning-data requirement as second axis — is my concrete “what next”: it upgrades our claim from an existence proof to a law, and directly arbitrates the axis.

Three things to remember

  • 1

    Output-space unification works at frontier scale. Re-parameterize every vision task as RGB, and one lightly-tuned generator checkpoint matches SAM 3, Depth Anything 3, and Lotus-2 — while still generating.

  • 2

    The capability was already there. Tiny tuning data, pseudo/synthetic labels only, emergent untrained compositions, metric scale from pretraining alone — the superficial-alignment hypothesis, now with a vision-side existence proof.

  • 3

    Our claim has precise edges. It’s a generator-checkpoint result, not a pixels-only-pretraining result; an intercept win, not a per-FLOP win; and abstention/confidence/cost remain genuinely open. The next real experiment is a scaling law, not another benchmark.

Extending the interface — what fits and what doesn’t

OutputEncoding designPitfall
Optical flow ✓Middlebury color wheel — hue = direction, saturation = magnitude; make it exact by fixing normalization in the prompt or reusing the depth power-transform on $\lVert v\rVert$None fundamental — flow is dense and image-shaped; natural fit
Keypoints ~Per-joint color disks; decode blob centroidsSub-pixel precision capped; occluded-joint conventions awkward
Boxes ✗Filled per-instance-color rectangles; decode extremal coordsOverlapping boxes occlude; corner-dots decode ambiguously — sparse structured output belongs in text tokens
Video tracking ✗Same instance must keep the same color across frames — condition each frame on the previous answer-frameTemporal color persistence isn’t guaranteed by the generator; drift accumulates
Uncertainty, if asked (1) $K$-seed sampling ensembles — per-pixel agreement/variance = epistemic uncertainty, principled at $K\times$ cost (self-consistency for vision) · (2) decode-distance to the nearest legal code — cheap, conflates noise with uncertainty · (3) AR token logprobs if the generator is autoregressive · (4) distill into a head with real logits for deployment-grade calibration.
