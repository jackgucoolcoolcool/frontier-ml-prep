How a Vision Transformer is trained — end to end

From raw pixels to a converged model: the data pipeline, the exact forward pass, the loss, the full optimizer recipe, why ViT famously needs scale, the pretraining objectives (supervised / CLIP / MAE / DINO), and transfer. With equations, figures, and runnable PyTorch.

Companion to Coding_Implementations_From_Scratch. ViT-Base/16 is the running example.

0 · Architecture recap (what we are training)

A ViT is a plain Transformer encoder applied to a sequence of image patches. Three things carry all the "vision-specific" logic; everything else is a standard encoder.

Figure 0. ViT-B/16 forward path. The only non-standard pieces: (a) patchify + linear projection, (b) the learned cls token, (c) additive learned positional embeddings. The rest is a vanilla pre-norm encoder; classification reads off the cls row.

ViT-Base/16 concretely: patch $16$, embedding dim $D=768$, depth $L=12$, heads $12$, MLP ratio $4$, $196$ patch tokens $+ 1$ cls $= 197$ tokens, ≈ 86M parameters. We take the architecture as given (see the coding doc for the module code) and focus on training it.

1 · The training loop at a glance

Training is the standard supervised-learning loop — the ViT-specific difficulty is not the loop, it is that the recipe (augmentation + regularization + optimizer schedule + data scale) must be right, because ViT has weak built-in visual priors.

Figure 1. The loop. Each stage below gets a section: augmentation (§2), forward (§3), loss (§4), optimizer + schedule (§5). Sections 6–8 explain why the recipe looks the way it does and how pretraining/fine-tuning differ.

2 · Data & augmentation — the part that actually decides success

For a CNN you can train ImageNet with light augmentation. For ViT on the same data, that recipe badly overfits — because a Transformer has no built-in translation equivariance or locality, so it must learn those invariances from data. You supply them two ways: more data (§6), or aggressive augmentation + regularization that manufactures the invariances. The DeiT recipe (ViT on ImageNet-1k alone) is the canonical proof that heavy augmentation substitutes for scale.

The standard strong recipe

TechniqueWhat it doesWhy ViT needs it
RandAugmentrandom chain of geometric/color opsmanufactures the invariances a CNN gets for free
Mixup $\tilde x = \lambda x_i + (1{-}\lambda)x_j$blends two images and their labelsstrong regularizer; smooths the loss landscape
CutMixpaste a patch of image B into A, mix labels by areaencourages using distributed evidence, not one region

import torchvision.transforms as T
train_tf = T.Compose([
    T.RandomResizedCrop(224, scale=(0.08, 1.0)),   # scale/aspect invariance
    T.RandomHorizontalFlip(),
    T.RandAugment(num_ops=2, magnitude=9),         # the workhorse
    T.ToTensor(),
    T.Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225]),
    T.RandomErasing(p=0.25),
])

Interview point. "Why does ViT need heavier augmentation than a ResNet?" — because a ResNet's convolutions hard-code locality and translation equivariance, so it generalizes from less data; ViT's attention is a global, permutation-equivariant operation with none of those priors, so the invariances must come from data or from augmentation that synthesizes them. This is the whole inductive-bias story in one sentence.

3 · The forward pass, precisely

With input batch $x \in \mathbb{R}^{B\times 3\times 224\times 224}$:

Patchify + project. A strided conv splits into non-overlapping patches and linearly projects each to $D$ dims — mathematically identical to "flatten each patch, apply one shared linear layer":

$$ z_0^{\text{patch}} = \text{Conv}_{k=s=16}(x) \in \mathbb{R}^{B\times 196\times D} $$

Prepend cls, add positions.

$$ z_0 = [\,x_{\text{cls}};\, z_0^{\text{patch}}\,] + E_{\text{pos}}, \qquad z_0 \in \mathbb{R}^{B\times 197\times D} $$

$L$ pre-norm blocks. For $\ell = 1,\dots,L$:

$$ z'_\ell = z_{\ell-1} + \text{MSA}\big(\text{LN}(z_{\ell-1})\big), \qquad z_\ell = z'_\ell + \text{MLP}\big(\text{LN}(z'_\ell)\big) $$

where multi-head self-attention with $h$ heads and per-head dim $d_h = D/h$ is

$$ \text{Attn}(Q,K,V) = \text{softmax}\!\Big(\frac{QK^\top}{\sqrt{d_h}}\Big)V . $$

Head. Read the cls row after a final LayerNorm:

$$ \hat y = W_{\text{head}}\;\text{LN}(z_L)_{[:,0]} \in \mathbb{R}^{B\times C}. $$
Three numerical details that are real bugs when wrong. (i) scale by $1/\sqrt{d_h}$ — the per-head dim, not $D$; (ii) softmax over the key axis (last); (iii) the head reads row 0 (cls), and there is a LayerNorm before the head. Getting the scale wrong makes attention logits blow up and training diverge at large $D$.

4 · The loss

Plain multi-class classification: softmax cross-entropy between logits $\hat y$ and target. With label smoothing $\varepsilon$, the one-hot target $y$ becomes a soft distribution

$$ \tilde y_c = (1-\varepsilon)\,y_c + \frac{\varepsilon}{C}, \qquad \mathcal{L} = -\sum_{c=1}^{C} \tilde y_c \,\log \text{softmax}(\hat y)_c . $$

Smoothing stops the model from driving a single logit to $+\infty$ (it never has a hard target to chase), which improves calibration and generalization. When mixup/cutmix is on, the target is already a two-hot mixture $\lambda\,y_i + (1{-}\lambda)\,y_j$, and the same cross-entropy against that soft target is used — so in a strong recipe the "hard label" essentially never appears.

# with mixup, targets are soft (B, C); use soft-target cross-entropy:
loss = torch.sum(-soft_target * torch.log_softmax(logits, dim=-1), dim=-1).mean()
# without mixup, nn.CrossEntropyLoss(label_smoothing=0.1) does it for you.

5 · Optimizer & schedule — the recipe that makes it converge

This is where most "my ViT won't train" problems live. The canonical settings:

KnobTypical valueWhy
OptimizerAdamWTransformers need adaptive LR; SGD underperforms badly here. AdamW ⇒ decoupled weight decay
Base LR$10^{-3}$ (scaled by batch)linear scaling: $\text{lr} = 5\times10^{-4}\cdot \text{batch}/512$
Warmup5–20 epochs, linear from 0essential — early Adam steps are noisy; skipping warmup is the #1 divergence cause
Schedulecosine decay to ~0smooth annealing outperforms step decay for ViT
Weight decay0.05–0.1strong reg; but exclude bias, LayerNorm, cls & pos embeddings
Grad clipglobal norm 1.0tames the occasional large step

Epochs300 (DeiT) / long pretrainViT wants long schedules

Figure 2. The schedule. Linear warmup from 0 avoids the noisy-early-Adam divergence; cosine decay anneals to near-zero for a clean final convergence. Nearly every modern ViT/transformer uses this shape.

import torch, math
# 1) parameter groups: no weight decay on norms / biases / embeddings
decay, no_decay = [], []
for n, p in model.named_parameters():
    if p.ndim == 1 or n.endswith(("cls_token", "pos_embed")):
        no_decay.append(p)          # LayerNorm weights, all biases, embeddings
    else:
        decay.append(p)
opt = torch.optim.AdamW(
    [{"params": decay, "weight_decay": 0.05},
     {"params": no_decay, "weight_decay": 0.0}],
    lr=1e-3, betas=(0.9, 0.999))

# 2) warmup + cosine LR (per-step)
def lr_at(step, warmup, total, base):
    if step < warmup:
        return base * step / warmup
    p = (step - warmup) / max(1, total - warmup)
    return 0.5 * base * (1 + math.cos(math.pi * p))
Failure mode. Train ViT with SGD, no warmup, light augmentation on ImageNet-1k → it underperforms a ResNet and may diverge early. Every one of those three is a known ViT pitfall; the recipe above is the accumulated fix.

6 · Why ViT needs scale — the inductive-bias crossover

The original ViT paper's central empirical result: on mid-sized data (ImageNet-1k) a ViT underperforms a comparable ResNet, but as pretraining data grows (ImageNet-21k → JFT-300M), ViT overtakes it and keeps scaling. The reason is the missing priors:

  • A CNN hard-codes locality and translation equivariance — correct visual assumptions, so it generalizes from little data but caps out sooner.
  • A ViT assumes almost nothing (attention is global + permutation-equivariant). With enough data it learns better, more flexible features than the hand-coded priors — but below a data threshold it has nothing to fall back on and overfits.

Figure 3. Schematic of the ViT paper's finding. Below the crossover, hand-coded conv priors win; above it, ViT's flexibility wins and keeps scaling. Two ways to get to the right of the crossover: (a) more pretraining data, or (b) manufacture the priors with heavy augmentation + distillation (DeiT) so IN-1k alone suffices.

The takeaway that drives every ViT recipe: you must supply the missing inductive bias somehow — through data scale, through augmentation/regularization, or through distillation from a CNN teacher (DeiT's extra "distillation token"). Modern practice usually combines large-scale (often self-supervised) pretraining with strong augmentation.

7 · Pretraining objectives — how the weights are actually learned at scale

"Training a ViT" almost never means supervised ImageNet from scratch anymore. It means pretrain on a large corpus with some objective, then transfer. The four dominant objectives, all training the same encoder, differ only in the loss and the data:

ObjectiveSignalLoss (sketch)What you get
Supervised (ViT, DeiT)class labelscross-entropy on cls tokenstrong classifier; needs labels
Contrastive / CLIP, SigLIPimage–text pairsInfoNCE between image & text embeddingsopen-vocab, language-aligned features — the VLM backbone
Masked image modeling (MAE, BEiT)the image itselfreconstruct masked patches (pixels/tokens)label-free; great fine-tuning init
Self-distillation (DINO/v2)the image itselfmatch student/teacher views, no labelsstrong frozen features, emergent segmentation

CLIP-style contrastive (the VLM-relevant one)

Given a batch of $N$ image–text pairs, encode both sides to unit vectors and pull matched pairs together, push mismatched apart, with a learned temperature $\tau$:

$$ \mathcal{L} = \tfrac{1}{2}\big(\mathcal{L}_{\text{img}\to\text{txt}} + \mathcal{L}_{\text{txt}\to\text{img}}\big), \quad \mathcal{L}_{\text{img}\to\text{txt}} = -\frac1N\sum_{i}\log\frac{\exp(\langle u_i,v_i\rangle/\tau)}{\sum_j \exp(\langle u_i,v_j\rangle/\tau)} $$

The image encoder here is a ViT; the softmax is over the other captions in the batch (in-batch negatives). This is how the vision tower of most VLMs is trained.

Masked image modeling (MAE)

Mask a high fraction of patches (~75%), encode only the visible ones, and a lightweight decoder reconstructs the missing patches under an $\ell_2$ pixel loss:

$$ \mathcal{L}_{\text{MAE}} = \frac{1}{|\mathcal{M}|}\sum_{p\in\mathcal{M}} \big\lVert \hat x_p - x_p\big\rVert_2^2 . $$

Because the encoder sees only 25% of tokens, pretraining is cheap; the encoder learns rich features that fine-tune extremely well. No labels required.

Résumé-relevant framing. For a multimodal model the ViT is usually pretrained contrastively or self-supervised, then either (a) fine-tuned end-to-end, or (b) frozen and connected to an LLM via a projector. "How do you train the vision tower of a VLM" = "CLIP/SigLIP contrastive pretraining on web image–text, optionally + MIM, then connect" — the whole of §7 is the answer.

8 · Fine-tuning & the resolution gotcha

Transfer = replace the head for the new task and continue training (full fine-tune) or freeze the backbone and train only a linear probe. Fine-tuning uses a smaller LR (e.g. $10^{-4}$ down to $10^{-5}$), shorter schedule, and often layer-wise LR decay (earlier layers get smaller LR, since they hold general features).

Changing input resolution → you must interpolate positional embeddings

Fine-tuning at higher resolution (a common accuracy trick) changes the number of patches, so the learned $E_{\text{pos}}$ — one vector per original grid position — no longer matches. Fix: reshape the patch-position embeddings to the old 2D grid, bilinearly interpolate to the new grid, and keep the cls position separate.

def interpolate_pos_embed(pos_embed, old_grid, new_grid):
    # pos_embed: (1, 1 + old_grid**2, D)  -> (1, 1 + new_grid**2, D)
    cls, patch = pos_embed[:, :1], pos_embed[:, 1:]
    D = patch.shape[-1]
    patch = patch.reshape(1, old_grid, old_grid, D).permute(0, 3, 1, 2)
    patch = torch.nn.functional.interpolate(
        patch, size=(new_grid, new_grid), mode="bicubic", align_corners=False)
    patch = patch.permute(0, 2, 3, 1).reshape(1, new_grid * new_grid, D)
    return torch.cat([cls, patch], dim=1)
Interview point. "You trained at 224 and want to fine-tune at 384 — what breaks?" → the positional embeddings. Interpolate them. This is the single most-asked ViT deployment detail.

9 · The full training step (putting it together)

model.train()
for step, (imgs, targets) in enumerate(loader):
    imgs, targets = imgs.cuda(), targets.cuda()
    imgs, soft_targets = mixup_fn(imgs, targets)     # mixup/cutmix -> soft labels

    for g in opt.param_groups:                        # warmup + cosine
        g["lr"] = lr_at(step, warmup_steps, total_steps, base_lr)

    with torch.cuda.amp.autocast():                   # mixed precision
        logits = model(imgs)
        loss = torch.sum(-soft_targets * torch.log_softmax(logits, -1), -1).mean()

    opt.zero_grad(set_to_none=True)
    scaler.scale(loss).backward()
    scaler.unscale_(opt)
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # grad clip
    scaler.step(opt); scaler.update()

    ema.update(model)                                 # EMA of weights for eval

That is a production-grade ViT training step: mixup soft targets, per-step LR schedule, AMP, gradient clipping, EMA. Everything else (distributed data-parallel, checkpointing, logging) wraps around this unchanged.

One-paragraph summary. Training a ViT is standard supervised (or self-supervised) learning wrapped around a plain Transformer encoder — but because attention lacks the conv priors of locality and translation equivariance, success hinges on supplying that inductive bias externally: through data scale (the JFT crossover), heavy augmentation + regularization (RandAug/mixup/cutmix/stochastic-depth/label-smoothing, the DeiT recipe), and a Transformer-appropriate optimizer schedule (AdamW, linear warmup, cosine decay, decoupled weight decay excluding norms/embeddings). At scale the encoder is usually pretrained contrastively (CLIP/SigLIP) or by masked/self-distillation (MAE/DINO), then transferred — and the recurring deployment detail is interpolating positional embeddings when resolution changes.

Test-time compute: deliberate reasoning vs best-of-N

Sequential self-refinement compounds — each step conditions on the previous attempt — so quality grows roughly Q(C) ≈ a + b·log C. Best-of-N only takes the max of independent draws, so its gains flatten (extreme-value scaling ≈ a + b·log log N).
