Chapter 1 · mirrors session W1Attention, from scratch

Stage 1 · what W1 asks firstScaled dot-product attention

One sentence you should be able to say cold: attention is a differentiable dictionary lookup — each query softly retrieves a mixture of values, weighted by how well its key matches.

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V, \qquad Q = XW_Q,\; K = XW_K,\; V = XW_V$$

Why $\sqrt{d_k}$ — the variance argument, which the probe asks verbatim: if $q, k$ have unit-variance i.i.d. entries, then $q\cdot k = \sum_{i=1}^{d_k} q_i k_i$ has variance $d_k$ (each term has variance 1, they add). Scores grow like $\sqrt{d_k}$, softmax saturates toward one-hot, and the gradient through softmax — $\frac{\partial p_i}{\partial z_j} = p_i(\delta_{ij} - p_j)$ — collapses to zero when any $p_i \to 1$. Dividing by $\sqrt{d_k}$ keeps score variance at 1 for any head size.

Stable softmax — the other half of stage 1. Softmax is shift-invariant, so subtract the row max before exponentiating; every exponent becomes $\le 0$ and nothing overflows:

$$\mathrm{softmax}(z)_i = \frac{e^{z_i - m}}{\sum_j e^{z_j - m}}, \qquad m = \max_j z_j$$ 
def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)   # stability: exponents <= 0
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

def attention(X, Wq, Wk, Wv):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv          # (T,dk) (T,dk) (T,dv)
    scores = Q @ K.T / np.sqrt(Wk.shape[1])    # (T,T)
    A = softmax(scores, axis=-1)               # each ROW sums to 1
    return A @ V                               # (T,dv)
traps the hidden tests spring
  • Inputs scaled ×60 → a naive np.exp overflows to inf, output goes NaN. The stability test exists because a textbook-correct answer still fails it.
  • Softmax over the wrong axis: rows (queries) must sum to 1, not columns. Symptom: every position gets the same output.
  • Scaling by $\sqrt{d_{model}}$ instead of $\sqrt{d_k}$ — matters the moment $d_v \ne d_k$ or heads appear.
Attention weight matrices (row = query, column = key; brighter = more weight, each row sums to 1). Left: full self-attention. Right: the same scores with a causal mask — the upper triangle is exactly zero, and each row renormalizes over its allowed prefix. Row 0 has no choice but itself.
Probe: why divide by √d_k? What goes wrong without it?
Unit-variance $q,k$ → dot product variance $d_k$ → scores grow like $\sqrt{d_k}$ → softmax saturates near one-hot → gradients through softmax vanish (the Jacobian rows go to zero) → training destabilizes. The division keeps score variance ~1 regardless of head size. Bonus point: this is also why attention logits are a classic fp16 overflow site.

Stage 2 · first extensionCausal masking

The mask must hit the scores, before softmax. Set disallowed entries to $-\infty$; then $e^{-\infty} = 0$ exactly and the softmax renormalizes over the allowed prefix:

$$S_{ij} \leftarrow \begin{cases} S_{ij} & j \le i \\ -\infty & j > i \end{cases} \qquad\Rightarrow\qquad p_{ij} = \frac{e^{S_{ij}}}{\sum_{j' \le i} e^{S_{ij'}}}$$

Why not zero the weights after softmax? Rows stop summing to 1 (outputs are wrongly scaled), and gradient still flows to masked positions. The $-\infty$ survives the stable-softmax max-subtraction because the diagonal is always allowed, so the row max is finite.

def attention(X, Wq, Wk, Wv, causal=False):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    scores = Q @ K.T / np.sqrt(Wk.shape[1])
    if causal:
        mask = np.tril(np.ones((len(X), len(X)), dtype=bool))  # True = allowed
        scores = np.where(mask, scores, -np.inf)               # BEFORE softmax
    return softmax(scores, axis=-1) @ V
traps
  • The leak test: it perturbs future tokens and asserts past outputs don't move. Masking after softmax, or an off-by-one triangle, fails it.
  • Breaking the causal=False path while adding the flag — regression tests exist in interviews too.
  • Interview tell: a causal LM with suspiciously low loss almost always means a leaking mask (the model copies the target from the input).
Probe: why −∞ before softmax rather than zeroing weights after?
Zeroing after breaks normalization — rows no longer sum to 1, outputs are scaled wrong, and masked positions still receive gradient. $-\infty$ before makes $e^{S}=0$ exactly and the softmax renormalizes over only the allowed positions. Variation to expect: the same logic with an arbitrary boolean mask (padding masks) — same np.where(mask, S, -inf), nothing special about the triangle.

Stage 3 · second extensionMulti-head attention

Multi-head is batched single-head over a split feature dimension. With $H$ heads and $d_h = d_{model}/H$:

$$\mathrm{head}_h = \mathrm{Attention}(XW_Q^{(h)}, XW_K^{(h)}, XW_V^{(h)}),\qquad \mathrm{MHA}(X) = \big[\mathrm{head}_1; \dots; \mathrm{head}_H\big]\, W_O$$

In code the per-head weights are one big matrix, and the split is a reshape + transpose. The reshape convention matters: split the last axis in place, then move heads to the front so NumPy's @ broadcasts over them:

def mha(X, Wq, Wk, Wv, Wo, n_heads, causal=False):
    T, d = X.shape
    dh = d // n_heads
    split = lambda W: (X @ W).reshape(T, n_heads, dh).transpose(1, 0, 2)  # (H,T,dh)
    Q, K, V = split(Wq), split(Wk), split(Wv)
    S = Q @ K.transpose(0, 2, 1) / np.sqrt(dh)        # (H,T,T) -- scale by HEAD dim
    if causal:
        S = np.where(np.tril(np.ones((T, T), dtype=bool)), S, -np.inf)
    out = (softmax(S, axis=-1) @ V)                    # (H,T,dh)
    return out.transpose(1, 0, 2).reshape(T, d) @ Wo   # concat heads, project
The head split is a reshape, not new parameters: one (d, d) projection viewed as H independent (d, d_h) projections. Scale by √d_h — the head dimension — not √d.
traps
  • reshape(H, T, dh) directly (without the transpose) scrambles tokens across heads — values look plausible, tests fail. The reshape splits the last axis; the transpose moves heads forward.
  • Scaling by $\sqrt{d}$ instead of $\sqrt{d_h}$ — off by $\sqrt{H}$.
  • A test compares 1 head vs 4 heads and asserts they differ — catches implementations that "split" but attend jointly anyway.
  • Variation to expect: cross-attention — Q from one sequence, K/V from another; scores go rectangular $(H, T_q, T_{kv})$ and output length follows the queries.
Probe: same parameters and FLOPs — why do heads help?
Each head gets its own softmax, so different heads attend to different relations simultaneously; a single head must commit to one convex mixture per query. It's a low-rank factorization of a richer attention operator. Empirically many heads are prunable after training, but training-time diversity of attention patterns is what you're buying.

Stage 3 · the golden answerMHA in einsum — project, reshape, name the axes

Same math as above, but all three transposes disappear: @ for the plain linear maps, reshape at the two head boundaries, einsum for the two lines where axes actually interact. Axis letters: q/k = reader/source token, h = head, e = per-head dim. The einsum mental model in one line: every distinct letter is an independent loop dial; a shared letter is one dial turning two tensors in lockstep (zip), different letters cross (all pairs), a letter dropped from the output gets summed, and output order is just the layout you receive.

def mha(X, Wq, Wk, Wv, Wo, n_heads, causal=True):
    T, D = X.shape
    dh = D // n_heads

    Q = X @ Wq                                   # (T, D)   project first
    K = X @ Wk
    V = X @ Wv

    Q = Q.reshape(T, n_heads, dh)                # (T, h, dh)  split heads
    K = K.reshape(T, n_heads, dh)                # (einsum can't split axes --
    V = V.reshape(T, n_heads, dh)                #  that's reshape's job)

    S = np.einsum('qhe,khe->hqk', Q, K) / np.sqrt(dh)     # (h, T, T)
    if causal:
        mask = np.tril(np.ones((T, T), dtype=bool))       # True = allowed
        S = np.where(mask, S, -np.inf)                    # BEFORE softmax
    A = softmax(S, axis=-1)                                # rows sum to 1

    O = np.einsum('hqk,khe->qhe', A, V)                    # (T, h, dh) token-major
    return O.reshape(T, D) @ Wo                            # (T, D) merge + project

Read each string as a sentence:

StringSentence
'qhe,khe->hqk'readers cross sources (two different token letters!), heads zipped, e dropped = the dot product. Writing h first in the output is the old transpose(1,0,2); contracting e between two token axes is the old K.transpose(0,2,1).
'hqk,khe->qhe'per head, each reader sums over sources k, grabbing source k's value — the weighted mix. Output qhe = token-major, so the final reshape(T, D) is legal with no cleanup transpose.
Why V must wear the k letter. Each cell (q, k) of the attention grid multiplies A[q,k] by whichever value vector its letter grabs (cell color = whose V). Left, 'hqk,khe': colors vary along the summation direction, so each row-sum is a real blend — out[q] is a mixed color. Right, 'hqk,qhe': every cell in a row grabs the row's own V, the weights factor out and sum to 1, and out[q] = v(q) exactly — attention silently becomes a no-op.
traps — each is one letter away from the golden answer, and none raises an error
  • 'hqk,qhe->qhe' — V locked to its reader: V is constant during the Σk, softmax rows sum to 1, and the whole layer returns V unchanged. Model trains; attention does nothing.
  • 'qhe,qhe->hq' — same letter for both token axes zips them: you get only the diagonal (each token scored against itself), never the (T, T) grid. Two independent axes need two letters even when they have the same length.
  • '...->hqe' followed by a bare reshape(T, D) — head-major memory gets re-cut across tokens. Either write ->qhe (free) or pay a transpose(1,0,2) first.
  • reshape(T, dh, n_heads) instead of (T, n_heads, dh) — reshape fills the last axis fastest, so this stripes dims across heads instead of giving each head a contiguous block.
Probe: read 'hqk,khe->qhe' out loud; what does 'hqk,qhe->qhe' compute instead?
Golden: "per head (zipped), for each reader q (kept), sum over sources k (dropped) the product of a weight and source k's value (V soldered to A on k), give it to me token-major." The one-letter variant reads V with the reader's dial, so during the sum over k nothing from V changes: out[q] = V[q] · ΣkA[q,k] = V[q] · 1 = V[q]. Identical output shape, zero information flow between positions — the einsum version of the leaking-mask class of silent bugs. Defensive test: assert the output is not allclose to V.

Stage 4 · the inference stageKV-cache decoding

At decode step $t$ you need one new query, but K/V over the whole history. Past K/V never change (causality), so cache them and append one row per step. Cost per step drops from rebuilding $O(t \cdot d^2 + t^2 d)$ to $O(d^2 + t\,d)$ — and no mask is needed, because the cache is the past:

def decode_step(x_t, Wq, Wk, Wv, cache):
    q = (x_t @ Wq)[None, :]                        # ONE query row
    k, v = (x_t @ Wk)[None, :], (x_t @ Wv)[None, :]
    K = k if cache["K"] is None else np.vstack([cache["K"], k])
    V = v if cache["V"] is None else np.vstack([cache["V"], v])
    A = softmax(q @ K.T / np.sqrt(K.shape[1]), axis=-1)   # attends over cache = past
    return (A @ V)[0], {"K": K, "V": V}
Why [None, :]? Isn't x_t @ Wq already a vector?
It is — 1-D, shape $(d_k,)$ — and that's the problem. [None, :] promotes it to a $(1, d_k)$ row matrix (same numbers, higher rank: $x \in \mathbb{R}^{d_k}$ vs $x^\top \in \mathbb{R}^{1\times d_k}$), because the cache invariant is K/V is a $(t, d_k)$ stack of rows, one per token — from step one. Step 1 seeds the cache with K = k directly: if k were 1-D, K.shape[1] raises IndexError, and in the sliding-window variant K[-window:] would slice the last $W$ features of one key instead of the last $W$ tokens — silent wrong shape. Kept 2-D, q @ K.T is $(1, t)$ — literally row $t$ of $\mathrm{softmax}(QK^\top/\sqrt{d_k})$ — and the final (A @ V)[0] strips the dummy row back to $(d_v,)$. With 1-D q that same [0] would return a scalar (the first feature), no error. One promotion up front buys a single 2-D code path shared with full attention, and NumPy 1-D arrays have no row/column identity anyway (.T is a no-op). Equivalent: .reshape(1, -1), np.atleast_2d, or x_t[None, :] @ Wq. Mechanics of the syntax itself: None in an index is np.newaxis — it consumes no existing axis and injects a length-1 axis at that slot (ndim: −1 per integer, +1 per None). Full write-ups: Q&A log Q46 (this line) & Q47 (None indexing).
Every line of decode_step, live (d_model=6, d_k=d_v=4, real math on seeded random weights). One press = one decode step: x_t is projected to one row each of q/k/v (the [None,:]), k and v are vstacked onto the cache, q scores every cached row (softmax row A sums to 1 — newest column included: the token attends to itself), and A mixes the cached values into the output. Past rows never change — that's the entire cache trick; no mask needed because the cache is the past.

The memory number to know cold (the probe asks for it): per token, cache size $= 2 \times L \times H_{kv} \times d_h \times \text{bytes}$. For 32 layers, 8 KV heads × 128 dims, fp16: $2 \cdot 32 \cdot 8 \cdot 128 \cdot 2 = 128\,\mathrm{KB/token}$ — a 100k-token agent trajectory holds ~13 GB per sequence. Decode is memory-bandwidth-bound on re-reading this cache every step; that's the entire motivation for GQA/MQA, sliding windows, and cache quantization.

Per-step attention FLOPs (arbitrary units) with and without a KV cache, and with a sliding window of 8. Without a cache each step recomputes all past K/V — quadratic total. The window caps both compute and memory at the cost of a bounded receptive field.
traps
  • The correctness invariant, tested exactly: feeding tokens one at a time must reproduce row $t$ of full causal attention at every step.
  • Adding a mask inside the decode step — there's no future in the cache to mask; it signals confusion about why the cache works.
  • Variation to expect: sliding-window cache — append first, then truncate to the last $W$ rows; the truncation order is the bug magnet.
Probe: KV-cache size per token, and why it dominates agent inference
128 KB/token for the 32-layer GQA example above → ~13 GB at 100k tokens. Every decode step re-reads the whole cache, so cache size sets both step latency and max batch size (throughput). Long-horizon agents are the worst case: enormous contexts, mostly idle weights, all bandwidth. Mitigations in order of adoption: GQA/MQA (shrink $H_{kv}$), sliding windows + attention sinks, cache quantization, paged attention.

Chapter 2 · mirrors session W2Norms & backprop by hand

Stages 1–2 · warm-up pairRMSNorm and LayerNorm

$$\mathrm{LN}(x) = \frac{x - \mu}{\sqrt{\sigma^2 + \varepsilon}} \odot \gamma + \beta \qquad\qquad \mathrm{RMS}(x) = \frac{x}{\sqrt{\tfrac{1}{d}\sum_i x_i^2 + \varepsilon}} \odot \gamma$$

Both normalize over the feature axis (last), per token — never over batch or time. RMSNorm deletes two things from LayerNorm: the mean subtraction and the bias $\beta$. That saves a reduction pass (~10–30% cheaper norm) and empirically loses nothing for transformers — the re-scaling is what stabilizes training; the re-centering was along for the ride. Hence Llama-class models use RMSNorm.

LayerNormRMSNorm
Mean subtractionyes → shift-invariantno → $x{+}c$ changes output
Variancebiased / population (ddof=0)— (mean of squares)
$\varepsilon$ placementinside the sqrt, added to $\sigma^2$inside the sqrt
Learned params$\gamma, \beta$$\gamma$ only
def rmsnorm(x, g, eps=1e-6):
    rms = np.sqrt((x ** 2).mean(axis=-1, keepdims=True) + eps)
    return x / rms * g

def layernorm(x, g, b, eps=1e-5):
    mu = x.mean(axis=-1, keepdims=True)
    var = x.var(axis=-1, keepdims=True)          # ddof=0: population variance
    return (x - mu) / np.sqrt(var + eps) * g + b
traps (the debug variants are built from exactly these)
  • keepdims=True on every reduction — without it, (B,T,d) inputs either crash or, worse, broadcast silently wrong.
  • Mean-subtracting in RMSNorm (that's LayerNorm) — caught by testing on inputs with nonzero mean.
  • $\sqrt{\sigma^2} + \varepsilon$ instead of $\sqrt{\sigma^2 + \varepsilon}$, and ddof=1 instead of 0 — both fail reference comparison.
Probe: pre-norm vs post-norm — why did everyone move to pre-norm?
Post-norm (original Transformer) normalizes after the residual add: the identity path itself passes through LN, so gradients at depth need warmup tricks or they diverge. Pre-norm keeps a clean identity path, $x + f(\mathrm{LN}(x))$ — well-behaved gradients at any depth, trains without warmup games. The cost is slightly weaker final quality per parameter, which is why hybrid schemes keep being revisited.
The blue line is the residual stream. Pre-norm keeps it untouched — that's the whole argument.

Stage 3 · the derivation stageSoftmax cross-entropy and its gradient

The one identity to hold in your head — derive it once, recite it forever. With logits $z$, label $y$, and $p = \mathrm{softmax}(z)$:

$$L = -\log p_y = -z_y + \log\!\sum_j e^{z_j} \qquad\Rightarrow\qquad \frac{\partial L}{\partial z_k} = -\,\mathbb{1}[k{=}y] + \frac{e^{z_k}}{\sum_j e^{z_j}} = p_k - \mathbb{1}[k{=}y]$$

The softmax Jacobian and the log collapse into prediction minus target — which is why every framework fuses softmax+CE into one op: better numerics and a trivial backward. For a mean over a batch of $B$, divide by $B$. Numerics: compute log-softmax directly, never log(softmax(x)) in two steps:

$$\log p_i = (z_i - m) - \log\!\sum_j e^{z_j - m}$$ 
def softmax_xent(logits, y):
    B = logits.shape[0]
    z = logits - logits.max(axis=1, keepdims=True)        # stability
    logp = z - np.log(np.exp(z).sum(axis=1, keepdims=True))
    loss = -logp[np.arange(B), y].mean()
    p = np.exp(logp)
    dlogits = p.copy()
    dlogits[np.arange(B), y] -= 1.0                        # p - onehot
    dlogits /= B                                           # grad of the MEAN
    return loss, dlogits
Loss $-\log p_y$ and gradient magnitude $|p_y - 1|$ as functions of the probability assigned to the correct class. The gradient is large exactly when the model is confidently wrong and fades as $p_y \to 1$ — self-paced learning built into the loss.
traps
  • Forgetting the $1/B$: your gradient is exactly $B\times$ too big — finite differences catch it instantly.
  • Logits at $\pm 1000$: two-step log(softmax) gives -inf/NaN; the fused log-softmax is exact.
  • Variation to expect: binary logistic with logits — same collapse, $\sigma(z) - y$, with $-\log\sigma(z) = \mathrm{logaddexp}(0, -z)$.
Probe: sketch the derivation of dL/dz = p − y
$L = -z_y + \log\sum_j e^{z_j}$. Differentiate: the first term gives $-\mathbb{1}[k{=}y]$; the second gives $e^{z_k}/\sum_j e^{z_j} = p_k$. Sum: $p_k - \mathbb{1}[k{=}y]$. No softmax-Jacobian gymnastics needed if you differentiate the log-sum-exp form directly — say that out loud, it reads as fluency.

Stage 4 · the boss stageTwo-layer MLP backward

Three reusable facts cover the whole backward pass:

1. Linear layer $y = xW + b$:   $\;\dfrac{\partial L}{\partial W} = x^\top \dfrac{\partial L}{\partial y}$,   $\dfrac{\partial L}{\partial b} = \sum_{\text{batch}} \dfrac{\partial L}{\partial y}$,   $\dfrac{\partial L}{\partial x} = \dfrac{\partial L}{\partial y} W^\top$. Get the transposes from shapes, not memory: $dW$ must be (in, out).

2. ReLU is a gate: $\;dh_{pre} = dh \odot \mathbb{1}[h_{pre} > 0]$ — gate on the pre-activation.

3. The head: $d\mathrm{logits} = (p - \mathrm{onehot})/B$ from stage 3.

Keep a running shape table as you code — dlogits (B,C) → dh (B,H) → dh_pre (B,H) → dW₁ (D,H). Shapes dictate every transpose.
def mlp_grads(X, y, W1, b1, W2, b2):
    B = X.shape[0]
    h_pre = X @ W1 + b1                    # forward, keeping intermediates
    h = np.maximum(h_pre, 0)
    logits = h @ W2 + b2
    z = logits - logits.max(axis=1, keepdims=True)
    p = np.exp(z); p /= p.sum(axis=1, keepdims=True)

    d = p.copy(); d[np.arange(B), y] -= 1.0; d /= B    # (B,C)
    dW2 = h.T @ d;        db2 = d.sum(axis=0)
    dh  = d @ W2.T                                     # (B,H)
    dh_pre = dh * (h_pre > 0)                          # ReLU gate
    dW1 = X.T @ dh_pre;   db1 = dh_pre.sum(axis=0)
    return {"dW1": dW1, "db1": db1, "dW2": dW2, "db2": db2}

The professional habit the session grades: check any hand-written gradient against central finite differences before trusting it — $\frac{f(w+h) - f(w-h)}{2h}$ with $h \approx 10^{-5}$, agreement to $10^{-4}$. The hidden tests are a finite-difference checker; in real life you write your own.

traps
  • Gating ReLU on $h$ instead of $h_{pre}$ (equivalent here, but the habit breaks for leaky/GELU) — and forgetting the gate entirely.
  • db = dy.mean(0) instead of sum(0) — the $1/B$ already lives in dlogits; dividing twice under-scales bias gradients.
  • Variation to expect: add L2 regularization — $+2\lambda W$ on weights, nothing on biases.
Probe: loss won't go down — first three debugging steps, in order
1) Finite-difference every gradient on a tiny batch — isolates a wrong formula. 2) Overfit a single batch of ~10 examples to ~zero loss — if it can't, the wiring is broken, not the data. 3) Check loss at init ≈ $\log C$ — catches bad init, label misindexing, softmax over the wrong axis. Then: LR sweep, per-layer gradient norms.

Chapter 3 · mirrors session F1Sampling & decoding

Stage 1 · the knobTemperature

$$p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

Temperature rescales logit gaps: $T{<}1$ sharpens toward the mode, $T{>}1$ flattens toward uniform, $T{\to}0$ is argmax, $T{\to}\infty$ is uniform. Handle $T{=}0$ as an explicit greedy branch before dividing. Everything else is the stable softmax from chapter 1.

The same 8 logits at four temperatures (computed live with the exact code below). At T=0.5 the top token dominates; at T=2 the tail matters again. In RL rollouts you sample warm for diversity — the advantage signal comes from disagreement between samples; for evals and tool calls you go cold.
def sample_probs(logits, temperature=1.0):
    if temperature == 0:                       # greedy: branch BEFORE dividing
        p = np.zeros_like(logits, dtype=float)
        p[np.argmax(logits)] = 1.0
        return p
    z = logits / temperature
    z = z - z.max()
    p = np.exp(z)
    return p / p.sum()
traps
  • $T{=}0$ → division by zero unless you branch first. The test asks for an exact one-hot.
  • Multiplying by $T$ instead of dividing — the $T{=}0.5$ test compares against softmax(logits/0.5) exactly.
  • Variation to expect: return log-probabilities (what PPO ratios need) — log-softmax in one pass, $T{=}0$ gives $0$ and $-\infty$.

Stage 2 · the filtersTop-k, top-p, min-p

All three truncate the unreliable tail, then renormalize. Order of operations in the graded task: temperature → top-k → top-p, renormalizing after every filter.

RuleKeepCharacter
top-kthe $k$ highest-probability tokensfixed count — ignores the shape of the distribution
top-p (nucleus)smallest prefix (sorted desc) with $\sum p \ge p$adaptive count — covers fixed mass; always ≥ 1 token
min-ptokens with $p_i \ge m \cdot \max_j p_j$adaptive to confidence; no sort needed; argmax always survives
One sorted distribution, three cutoffs: top-k=4 keeps a fixed count; top-p=0.9 keeps the smallest prefix reaching 90% mass; min-p=0.1 keeps everything within 10× of the top token. When the model is confident (shown), min-p and top-p cut deep into the tail while top-k blindly admits it.
order = np.argsort(-p)                       # original vocab indices, desc
cs = np.cumsum(p[order])
cnt = int(np.searchsorted(cs, top_p)) + 1    # smallest prefix with cumsum >= p
keep = order[:cnt]
m = np.zeros_like(p); m[keep] = p[keep]
p = m / m.sum()                              # renormalize -- every time
traps
  • Off-by-one at the cutoff: "smallest prefix with cumsum ≥ p" — searchsorted + 1, and at least one token always survives (tested with top-p=0.1 on a peaked distribution).
  • Sorting p itself and losing vocab positions — filter via indices from argsort.
  • Forgetting to renormalize after a filter — samples are silently biased; the tests check sum == 1.
Probe: why did nucleus (top-p) replace top-k as the default?
A fixed $k$ ignores distribution shape: when the model is confident, $k{=}50$ admits garbage; when genuinely uncertain, it cuts valid options. Top-p adapts — it truncates the tail (where probability estimates are worst) while preserving calibrated uncertainty. Min-p pushes the same idea further with a confidence-relative threshold and no sort.

Stage 3 · the anti-loop knobsRepetition penalties

CTRL-style multiplicative penalty, for every already-generated token $t$ with penalty $\rho > 1$:

$$z_t \leftarrow \begin{cases} z_t / \rho & z_t > 0 \\ z_t \cdot \rho & z_t \le 0 \end{cases}$$

The asymmetry is the interview question: both branches must push toward less likely. Dividing a negative logit by $\rho$ would move it toward zero — i.e. boost it. The additive (OpenAI-style) scheme has no asymmetry to trip on: $z_t \leftarrow z_t - \alpha\,\mathbb{1}[\mathrm{count}>0] - \beta\,\mathrm{count}(t)$ (presence $\alpha$, frequency $\beta$).

traps
  • The negative-logit test: penalty 2.0 on logit −2.0 must give −4.0, not −1.0.
  • Mutating the caller's logits array — tests assert the input is untouched.
  • Known failure mode to volunteer: penalties hit legitimate repeats too (code identifiers, "the") — why DRY-style n-gram penalties exist.

Stage 4 · inference-time alignmentBest-of-n

Sample $n$ candidates, score with a reward model, keep the argmax (ties → earliest). It's policy improvement without touching weights, and its distance from the base policy is tightly bounded:

$$\mathrm{KL}\big(\pi_{\mathrm{BoN}} \,\|\, \pi\big) \;\le\; \log n - \frac{n-1}{n}$$

— about 2.35 nats at $n{=}16$. That bound is why best-of-n is the gentle, analyzable optimizer: compare with RL, which can move arbitrarily far. The catch as $n$ grows: you increasingly select the reward model's errors — Goodhart / reward over-optimization. Best-of-n is also the workhorse behind rejection-sampling distillation (SFT on best-of-n outputs) and verifier-based test-time compute.

Illustrative over-optimization: proxy reward (what the RM says) climbs monotonically with n, true quality peaks and then decays as selection starts exploiting RM blind spots. The gap is Goodhart's law, measured. Mitigations: modest n, better/ensembled RMs, KL-aware selection, verifiable rewards.
def best_of_n(generate, reward, n, rng):
    best_t, best_r = None, -float("inf")
    for _ in range(n):
        t = generate(rng)
        r = reward(t)
        if r > best_r:              # strict >: earliest wins ties
            best_t, best_r = t, r
    return best_t, best_r
traps
  • Tie-breaking: strict > so the earliest sample wins — tested with a constant reward.
  • RNG discipline: call generate(rng) exactly $n$ times in order; extra rng consumption breaks determinism.
  • Variation to expect: self-consistency (majority voting) — agreement replaces the reward model; same earliest-wins tie rule.
Probe: how does best-of-n relate to RLHF, and what happens as n → large?
It's inference-time policy improvement against the RM with KL ≈ $\log n - (n{-}1)/n$ from the base — a bounded, analyzable optimizer. Large $n$ → reward over-optimization: samples that exploit RM blind spots outscore genuinely good ones. It doubles as a data engine (rejection-sampling SFT) and as test-time compute with verifiers.

Chapter 4 · mirrors session F2 — both coding interviewers' specialtyPost-training losses: RM → DPO → PPO → GRPO

This ladder is the alignment stack in miniature. The through-line to say out loud at some point: every method here is a different answer to one question — where does the training signal come from, and how do you stop the policy from running away with it?

Stage 1 · the signal sourceReward model: Bradley–Terry

Humans are unreliable at absolute scores but reliable at pairwise comparisons, so we model preferences with a latent scalar reward per response and a logistic link (the Bradley–Terry model):

$$P(y_w \succ y_l) = \sigma\big(r(y_w) - r(y_l)\big) \qquad\Rightarrow\qquad \mathcal{L}_{RM} = -\,\mathbb{E}\Big[\log \sigma\big(r_\theta(y_w) - r_\theta(y_l)\big)\Big]$$

Two consequences worth stating unprompted. Identifiability: only reward differences appear, so the absolute scale is free — RM outputs need normalization (whitening, or the KL anchor in PPO) before use. Numerics: $-\log\sigma(x) = \log(1 + e^{-x}) = \mathrm{softplus}(-x)$, which the naive form overflows for $x \ll 0$. One stable primitive covers this whole chapter:

$$-\log\sigma(x) = \mathrm{logaddexp}(0, -x) \approx \begin{cases} e^{-x} \to 0 & x \gg 0 \\ -x & x \ll 0 \text{ (exactly linear)} \end{cases}$$ 
def rm_loss(r_chosen, r_rejected):
    margin = r_chosen - r_rejected
    return np.mean(np.logaddexp(0.0, -margin))   # -log sigmoid, exact at ±1000

# what you'd actually log during RM training (the "with metrics" variation):
def rm_stats(r_chosen, r_rejected):
    margin = r_chosen - r_rejected
    loss = np.mean(np.logaddexp(0.0, -margin))
    acc = float(np.mean(margin > 0))              # strict >: ties count as wrong
    return loss, acc, float(margin.mean())
The Bradley–Terry loss $-\log\sigma(m)$ and its gradient weight $\sigma(-m)$ as functions of the reward margin. Correct-and-confident pairs (right) contribute ~zero gradient; the loss is exactly linear in the wrong tail (left) — softplus never explodes, which is why logaddexp is the only safe implementation.
traps the hidden tests spring
  • Margins of ±1000: -np.log(sigmoid(m)) overflows to inf/NaN; the test asserts the loss ≈ 1000 exactly (linear tail).
  • A tie ($r_c = r_r$) must give loss $\log 2 \approx 0.693$ — a hand-check the interviewer can do on sight.
  • Metrics variation: accuracy uses strict $>$ — a tie counts as wrong.
Probe: why pairwise comparisons instead of absolute scores, and what does BT assume?
Human absolute scores drift across annotators and time; side-by-side ranking is far more consistent. BT assumes a scalar latent quality with a logistic link — transitivity, no context effects (both violated in practice, which is partly why RMs are imperfect). And only differences are identified: the scale is a free parameter, hence reward normalization before RL.

Stage 2 · skip the RMDPO — and the derivation you should own

The RLHF objective is reward maximization with a KL leash to a frozen reference:

$$\max_\pi \; \mathbb{E}_{y\sim\pi}\big[r(y)\big] \;-\; \beta\,\mathrm{KL}\big(\pi \,\|\, \pi_{\mathrm{ref}}\big)$$

This has a closed-form optimum (write it, it's two lines): the Gibbs distribution $\pi^*(y) = \frac{1}{Z}\,\pi_{\mathrm{ref}}(y)\,e^{r(y)/\beta}$. Invert it to express the reward in terms of the policy:

$$r(y) = \beta \log\frac{\pi^*(y)}{\pi_{\mathrm{ref}}(y)} + \beta \log Z$$

Substitute into Bradley–Terry — and $\beta\log Z$, the intractable part, cancels in the pairwise difference. That cancellation is DPO:

$$\mathcal{L}_{DPO} = -\log\sigma\!\Big(\underbrace{\beta\log\tfrac{\pi(y_w)}{\pi_{\mathrm{ref}}(y_w)}}_{\hat r_w} \;-\; \underbrace{\beta\log\tfrac{\pi(y_l)}{\pi_{\mathrm{ref}}(y_l)}}_{\hat r_l}\Big)$$

The $\hat r$ terms are implicit rewards — your policy is secretly a reward model. The gradient tells you the training dynamics: $\nabla\mathcal{L} = -\beta\,\sigma(-h)\big[\nabla\log\pi(y_w) - \nabla\log\pi(y_l)\big]$ where $h$ is the margin — pairs the model gets wrong (small $h$) get the largest updates, and the weight $\sigma(-h)$ saturates: once a pair is won, DPO stops pushing... almost. That saturation is slow enough that easy pairs still drift, which motivates IPO (the variation): regress the margin to a fixed target instead of maximizing it —

$$\mathcal{L}_{IPO} = \Big(h - \tfrac{1}{2\beta}\Big)^2, \qquad h = \log\tfrac{\pi(y_w)}{\pi_{\mathrm{ref}}(y_w)} - \log\tfrac{\pi(y_l)}{\pi_{\mathrm{ref}}(y_l)} \;\;(\text{no }\beta\text{ inside})$$ 
def dpo_loss(logp_c, logp_r, ref_c, ref_r, beta=0.1):
    h = beta * ((logp_c - ref_c) - (logp_r - ref_r))   # implicit reward margin
    loss = np.logaddexp(0.0, -h).mean()                 # -log sigmoid(h), stable
    return loss, h.mean()                               # log the margin: run health

def ipo_loss(logp_c, logp_r, ref_c, ref_r, beta=0.1):
    h = (logp_c - ref_c) - (logp_r - ref_r)             # beta NOT inside h
    return np.mean((h - 1.0 / (2 * beta)) ** 2)         # regress to target 1/(2β)
Per-pair loss vs the log-ratio margin $h$. DPO ($-\log\sigma(\beta h)$) saturates — won pairs stop contributing, but only asymptotically, and larger β saturates faster (stronger KL anchor). IPO is a parabola with a minimum at the target margin $1/(2\beta)$: it actively pulls back pairs that overshoot, which is the overfitting fix.
traps
  • The grouping: it's (policy − reference) per response, then chosen − rejected. Mis-pairing silently corrupts the objective while the loss still goes down.
  • β inside the sigmoid for DPO, but in the target for IPO — the tests hand-check both (h=1, β=0.1 → IPO loss (1−5)² = 16).
  • Stability again: extreme log-prob gaps must not overflow — same logaddexp.
Probe: what role does the reference model play, and what happens as β → 0?
The reference anchors the implicit reward $\hat r = \beta\log(\pi/\pi_{\mathrm{ref}})$ — DPO is exactly the KL-constrained RLHF optimum in closed form, and π_ref must stay frozen or the reward definition moves under you. Small β = weak leash: the policy chases preferences far off-distribution — margins grow while the log-prob of even the chosen responses can fall (mass leaves both). β→0 is an unconstrained preference optimizer: degeneration. Bonus: monitor chosen log-prob separately from the margin; the margin alone hides this failure.

Stage 3 · on-policy RLPPO's clipped surrogate — pessimism, precisely

Policy gradient with importance sampling lets you reuse rollouts from $\pi_{\mathrm{old}}$ for a few minibatch epochs: with ratio $\rho = \frac{\pi(a|s)}{\pi_{\mathrm{old}}(a|s)} = e^{\log\pi - \log\pi_{\mathrm{old}}}$, the surrogate $\mathbb{E}[\rho A]$ is only a valid local approximation near $\rho = 1$. Unconstrained, a few high-advantage tokens drive huge updates and the policy collapses. PPO's fix is a pessimistic lower bound:

$$J = \mathbb{E}\Big[\min\big(\rho A,\;\; \mathrm{clip}(\rho,\, 1{-}\varepsilon,\, 1{+}\varepsilon)\, A\big)\Big], \qquad \mathcal{L} = -J$$

The min — not the clip — is the idea. Work the four quadrants once and you'll never sign-flip it:

Casemin picksGradientMeaning
$A>0$, $\rho > 1{+}\varepsilon$clipped $(1{+}\varepsilon)A$zerostop over-reinforcing a good action
$A>0$, $\rho < 1{-}\varepsilon$unclipped $\rho A$flowskeep pushing probability up
$A<0$, $\rho > 1{+}\varepsilon$unclipped $\rho A$ (more negative)flowsnever protected from getting worse
$A<0$, $\rho < 1{-}\varepsilon$clipped $(1{-}\varepsilon)A$zerostop over-suppressing
def ppo_loss(logp_new, logp_old, adv, clip_eps=0.2):
    ratio = np.exp(logp_new - logp_old)
    clipped = np.clip(ratio, 1.0 - clip_eps, 1.0 + clip_eps)
    objective = np.minimum(ratio * adv, clipped * adv)   # min handles BOTH signs
    return -objective.mean()                              # never branch on sign(A)
The canonical PPO figure: per-token objective vs ratio ρ at ε = 0.2. For A = +1 the objective flattens above 1+ε (no reward for overshooting); for A = −1 it flattens below 1−ε but keeps falling above 1+ε — the asymmetry is the pessimism. If you can draw this from memory, the stage is yours.

In RLHF the same ratio shows up a second way (the variation): the KL leash is often applied as reward shaping on each token instead of a loss term:

$$\tilde r_t = r_t - \beta\big(\log\pi(a_t) - \log\pi_{\mathrm{ref}}(a_t)\big)$$

— drift above the reference gets taxed in the reward itself, and the mean of $(\log\pi - \log\pi_{\mathrm{ref}})$ is the KL estimate you'd chart in every RLHF run.

traps
  • The four-quadrant test uses ratios {1.5, 0.5} × advantages {+1, −1} and checks the exact mean — any branch-on-sign(A) shortcut gets at least one quadrant wrong.
  • Hand-check on sight: ρ=1.5, A=1, ε=0.2 → min(1.5, 1.2) = 1.2 → loss −1.2.
  • Inside the trust band the loss must equal the plain surrogate exactly — clipping too early fails it.
  • KL-shaping variation: sign check — policy above reference must reduce reward.
Probe: what failure does the clip prevent, and why is the min essential?
Off-policy drift within an epoch: the surrogate is only locally valid, and unconstrained minibatch updates on high-advantage tokens cause destructive policy jumps. Clip alone would also cap the penalty when an update makes things worse (A<0, ρ large); the min keeps the objective a lower bound — gradients stop when overshooting in your favor, never when degrading.

Stage 4 · drop the criticGRPO and RLOO — critic-free baselines

PPO's value network exists for one reason: variance reduction via a baseline. If you sample $N$ responses per prompt, the group itself is a Monte-Carlo baseline and the critic — a whole model's worth of memory and its own lag pathologies — can be deleted. GRPO (the DeepSeek-R1 recipe) normalizes within the group:

$$A_{ij} = \frac{r_{ij} - \mathrm{mean}(r_{i\cdot})}{\mathrm{std}(r_{i\cdot}) + \epsilon}$$

The std division is where the bodies are buried (the probe): a nearly-solved prompt with rewards $\{0.99, 1, 1, 1\}$ has tiny variance, so its meaningless 0.01 gap gets amplified to a full-sized advantage — difficulty bias: easy and impossible prompts get overweighted relative to informative ones. Dr. GRPO drops the std for exactly this reason. The cleaner cousin (the variation) is RLOO — leave-one-out, an unbiased baseline because sample $j$'s baseline never includes sample $j$:

$$A_{ij} = r_{ij} - \frac{1}{N-1}\sum_{k \ne j} r_{ik} \;=\; r_{ij} - \frac{S_i - r_{ij}}{N-1}, \qquad S_i = \sum_k r_{ik}$$ 
def grpo_advantages(rewards, eps=1e-6):
    mean = rewards.mean(axis=1, keepdims=True)     # per-prompt MC baseline
    std = rewards.std(axis=1, keepdims=True)       # population std
    return (rewards - mean) / (std + eps)          # eps on STD: all-equal group -> 0

def rloo_advantages(rewards):
    N = rewards.shape[1]
    row_sum = rewards.sum(axis=1, keepdims=True)
    return rewards - (row_sum - rewards) / (N - 1) # own sample excluded: unbiased
Difficulty bias, visible: an easy prompt (rewards 0.99, 1, 1, 1) and a hard prompt (0.1, 0.9, 0.5, 0.3). GRPO's std-normalization inflates the easy prompt's trivial 0.01 gap to the same advantage magnitude as the hard prompt's genuinely informative spread. RLOO keeps advantages on the reward scale — the easy prompt correctly contributes almost nothing.
traps
  • ε goes on the std, not the variance: an all-equal group must give exactly 0 (no signal), not $0.01/\sqrt{\epsilon}$-sized noise.
  • Per-row statistics with keepdims — normalizing across the whole batch mixes prompts and destroys the baseline logic.
  • RLOO hand-check: rewards [1, 2, 3] → advantages [−1.5, 0, 1.5] (each vs the mean of the others).
  • Both must be exactly zero on a uniform group — the test that catches copy-pasted z-scoring.
Probe: why can GRPO drop the value network, and what bias does the std introduce?
The critic is just a learned baseline; N samples per prompt give a Monte-Carlo baseline for free — cost shifts from critic memory/training to N× rollouts. The std division whitens per-prompt but amplifies near-zero-variance (too-easy/too-hard) prompts into full-strength gradients — difficulty bias, the Dr. GRPO fix. RLOO's leave-one-out mean is unbiased (own sample excluded) and keeps the reward scale.

Either coding round may open with one of these. They're not hard — the bar is speed, edge cases without prompting, and complexity stated unasked.

Stage 1 · sweep patternMerge intervals (and insert-interval)

Sort by start, then one linear pass: if the next interval starts at or before the current merged end, extend; otherwise emit. Two details carry the whole problem: touching merges ($s \le \mathrm{end}$, and say out loud that you're choosing that semantic), and extension uses $\mathrm{end} \leftarrow \max(\mathrm{end}, e)$ — the max is what survives nested intervals.

The two test cases that catch 90% of broken merges: nested intervals (needs max) and touching endpoints (needs ≤).
def merge_intervals(intervals):
    if not intervals:
        return []
    intervals = sorted(intervals, key=lambda iv: iv[0])   # O(n log n) dominates
    out = [list(intervals[0])]
    for s, e in intervals[1:]:
        if s <= out[-1][1]:                    # overlap OR touch
            out[-1][1] = max(out[-1][1], e)    # max: the nested-interval fix
        else:
            out.append([s, e])
    return out

Insert-interval variation (input already sorted & disjoint — don't re-sort, that wastes the precondition): three phases, one pass, $O(n)$ — copy intervals ending strictly before the new one; absorb every overlapper into the new interval with min/max; copy the rest.

traps
  • Empty input, unsorted input, fully-nested intervals, touching endpoints — all tested; handle them before being asked.
  • Insert variation: "absorb" must take min of starts AND max of ends — the new interval can extend in both directions.
  • Complexity unasked: sort $O(n\log n)$, pass $O(n)$; already-sorted input → $O(n)$.

Sliding window with a last-seen map. The single trap that decides pass/fail is the stale index: when a repeat is found behind the current window, the left pointer must never move backward:

$$\mathrm{left} \leftarrow \max(\mathrm{left},\; \mathrm{seen}[c] + 1)$$

def longest_unique(s):
    seen, left, best = {}, 0, 0
    for right, c in enumerate(s):
        if c in seen:
            left = max(left, seen[c] + 1)   # never backward
        seen[c] = right
        best = max(best, right - left + 1)
    return best

# at-most-k-distinct variation: counts dict + shrink-while-invalid
def longest_k_distinct(s, k):
    if k == 0: return 0
    counts, left, best = {}, 0, 0
    for right, c in enumerate(s):
        counts[c] = counts.get(c, 0) + 1
        while len(counts) > k:              # shrink until valid again
            lc = s[left]
            counts[lc] -= 1
            if counts[lc] == 0: del counts[lc]   # keep len() == true distinct count
            left += 1
        best = max(best, right - left + 1)
    return best
traps
  • "abba" — the stale-index test, named in the failure message if you miss it.
  • k-distinct variation: forgetting del at count zero inflates the distinct count forever; k=0 and empty string are tested.
  • Say it unasked: $O(n)$ time (each pointer only moves forward), $O(\min(n, |\Sigma|))$ space.
Probe: why is the max() in the left-pointer update necessary?
A repeat found before the current window would drag left backward ("abba": the second 'a' has seen index 0, but left is already 2) — re-admitting a duplicate and overcounting. max() makes the pointer monotone, which is also exactly the property that makes the algorithm $O(n)$.

§1 · the skeletonThe decoder block, and where the parameters live

A modern (Llama-class) decoder block is two pre-norm residual sub-layers:

$$x \leftarrow x + \mathrm{MHA}\big(\mathrm{RMSNorm}(x)\big) \qquad\qquad x \leftarrow x + \mathrm{FFN}\big(\mathrm{RMSNorm}(x)\big)$$

and the full model is: token embedding → $L$ blocks → final RMSNorm → unembedding (often weight-tied to the embedding). The parameter accounting is a probe you should do from memory. Per block, with width $d$:

ComponentWeightsParams
Attention$W_Q, W_K, W_V, W_O$ (each $d{\times}d$; less for K,V under GQA)$4d^2$
SwiGLU FFN$W_g, W_u \in \mathbb{R}^{d \times d_{ff}}$, $W_d \in \mathbb{R}^{d_{ff} \times d}$ with $d_{ff} \approx \tfrac{8}{3}d$$3\,d\,d_{ff} \approx 8d^2$
Total per block$\approx 12d^2$  →  $N \approx 12\,L\,d^2$

Two-thirds of a dense transformer is FFN. Say that sentence and you've already explained why MoE replaces the FFN and not the attention, and why FFN layers are where "knowledge" probing consistently points.

The pre-norm decoder block. The residual stream is untouched by anything except additions — every sub-layer reads a normalized copy and writes back a delta.
def block(x, p):            # composes entirely from chapters 1-2
    x = x + mha(rmsnorm(x, p.g1), p.Wq, p.Wk, p.Wv, p.Wo, p.n_heads, causal=True)
    x = x + swiglu_ffn(rmsnorm(x, p.g2), p.Wg, p.Wu, p.Wd)
    return x

def swiglu_ffn(x, Wg, Wu, Wd):
    silu = lambda z: z / (1.0 + np.exp(-z))       # z * sigmoid(z)
    return (silu(x @ Wg) * (x @ Wu)) @ Wd          # gate ⊙ up, then down
Probe: why SwiGLU over the classic ReLU MLP, and why d_ff = 8/3·d?
The gate makes the FFN's transformation input-dependent (multiplicative interactions the additive path can't express) — consistently better loss at equal params (the GLU-variants result; "we offer no explanation but gratitude" is a fine joke to deploy). 8/3: SwiGLU has three matrices instead of two, so shrinking $d_{ff}$ from $4d$ to $\tfrac{2}{3}\cdot 4d$ keeps the parameter count matched to the classic $4d$ MLP.

§2 · positionRoPE — rotate, don't add

RoPE encodes position by rotating each (q, k) feature pair $j$ by an angle proportional to its position, with per-pair frequency $\theta_j$:

$$\begin{pmatrix} x_{2j} \\ x_{2j+1} \end{pmatrix} \!\leftarrow\! \begin{pmatrix} \cos m\theta_j & -\sin m\theta_j \\ \sin m\theta_j & \cos m\theta_j \end{pmatrix}\! \begin{pmatrix} x_{2j} \\ x_{2j+1} \end{pmatrix}, \qquad \theta_j = b^{-2j/d},\;\; b = 10{,}000$$

The property that makes it the default — rotations compose, so the attention logit depends only on relative position:

$$\big\langle R(m\theta)\,q,\; R(n\theta)\,k \big\rangle = \big\langle q,\; R\big((n{-}m)\theta\big)\,k \big\rangle \;=\; g(q, k, \,n - m)$$

Absolute positions cancel; only the offset survives. The frequency spectrum runs from fast ($\theta_0 = 1$: distinguishes adjacent tokens) to glacial ($\theta_{d/2} \approx 1/b$: distinguishes document-scale distances) — a multi-resolution clock. Apply it to q and k only, after projection, never to v — v carries content, and rotating it would corrupt the mixture that attention outputs.

def rope(x, positions, base=10000.0):
    d = x.shape[-1]
    inv_freq = base ** (-np.arange(0, d, 2) / d)     # θ_j per feature pair
    ang = positions[:, None] * inv_freq[None, :]      # (T, d/2)
    cos, sin = np.cos(ang), np.sin(ang)
    x1, x2 = x[:, 0::2], x[:, 1::2]
    out = np.empty_like(x)
    out[:, 0::2] = x1 * cos - x2 * sin                # 2-D rotation per pair
    out[:, 1::2] = x1 * sin + x2 * cos
    return out
# usage: q = rope(X @ Wq, pos); k = rope(X @ Wk, pos); v untouched
Attention logit between identical q and k as a function of relative distance (d=64, computed live as $\sum_j \cos(\Delta\,\theta_j)$). With base 500 the signal decays and aliases within a few hundred tokens; base 10k holds structure to ~2k; base 500k stays coherent far beyond — which is exactly why long-context models raise the base (or interpolate positions: NTK/YaRN rescale the frequency spectrum so trained phase ranges are never exceeded).
traps & probe fodder
  • Applying RoPE to v, or before the projections — both wrong; the relative-position property only holds for the q·k inner product.
  • Beyond trained length, phases $m\theta_j$ leave the range the model ever saw → attention garbage. Fixes ranked: raise the base for pretraining; position interpolation / NTK / YaRN for post-hoc extension; with the honest note that all of them trade some short-range resolution.
  • KV-cache interaction: rotate k before caching (standard, cache stores rotated keys keyed to absolute position).
Probe: derive why RoPE gives relative position (2 lines)
Rotation matrices satisfy $R(a)^\top R(b) = R(b-a)$. So $\langle R(m\theta)q, R(n\theta)k\rangle = q^\top R(m\theta)^\top R(n\theta) k = q^\top R((n{-}m)\theta)k$ — absolute $m, n$ appear only through their difference. Additive learned positions have no such cancellation, and sinusoidal APE only approximates it through the attention matrix.

§4 · sparse capacityMixture of Experts

Replace the FFN with $E$ expert FFNs and a learned router; each token runs only its top-$k$ (usually 2):

$$y = \sum_{i \,\in\, \mathrm{top\text{-}}k(\ell)} g_i \, \mathrm{FFN}_i(x), \qquad g = \mathrm{softmax}\big(\ell_{\mathrm{top\text{-}}k}\big),\quad \ell = x W_r$$

This decouples parameters from FLOPs: capacity (knowledge) scales with $E$, compute per token stays at $k$ experts. The catch is that routing is a load-balancing problem: the router self-reinforces (popular experts get more gradient, get better, get more popular — router collapse), so training adds an auxiliary loss. With $f_i$ = fraction of tokens routed to expert $i$ and $P_i$ = mean router probability:

$$\mathcal{L}_{\mathrm{aux}} = \alpha \cdot E \sum_{i=1}^{E} f_i \, P_i \qquad \text{(minimized when routing is uniform; } f \text{ is non-differentiable, } P \text{ carries the gradient)}$$ 
def moe_ffn(x, W_router, experts, k=2):        # experts: list of (Wg, Wu, Wd)
    logits = x @ W_router                       # (T, E)
    out = np.zeros_like(x)
    for t in range(x.shape[0]):                 # per-token top-k routing
        idx = np.argsort(-logits[t])[:k]
        g = softmax(logits[t, idx])             # renormalize over the CHOSEN k
        for i, w in zip(idx, g):
            out[t] += w * swiglu_ffn(x[t:t+1], *experts[i])[0]
    return out                                  # real systems: batched expert-parallel dispatch
Total vs active parameters. MoE models sit far above the dense diagonal: Mixtral 8×7B holds 47B parameters but computes with ~13B per token; DeepSeek-V3 holds 671B and activates 37B. The gap is free capacity at fixed FLOPs — paid for in memory footprint, routing complexity, and expert-parallel communication at inference.
traps & probe fodder
  • Renormalize the gate over the selected k experts, not all E — otherwise outputs shrink as E grows.
  • Params ≠ capability at equal FLOPs comparisons: an 8×7B MoE is not "a 47B model"; compare against dense models matched on either params or FLOPs and say which.
  • Capacity factor and token dropping: fixed expert buffers mean overflow tokens get dropped or overflow-routed — a real quality/throughput dial.
  • Modern refinements to name: fine-grained experts (more, smaller) + shared always-on experts (DeepSeek), aux-loss-free balancing via per-expert bias (V3), and the deployment reality — all experts must fit in memory, so MoE trades bandwidth for capacity, not memory.
Probe: why does MoE replace the FFN and not attention, and what breaks at inference?
FFN is ⅔ of parameters and per-token (no cross-token interaction), so it shards cleanly into experts; attention is where tokens mix — sparse attention is a different research axis. At inference: all experts must be resident (memory), tokens in a batch fan out to different experts (all-to-all communication, expert parallelism), and small batches under-utilize experts — MoE shines at large-batch serving and hurts latency-sensitive small-batch decode.

§5 · vision inViT → contrastive pretraining → VLM connector

Patchify. A ViT is a transformer whose "tokens" are flattened image patches: a $H{\times}W$ image with patch size $P$ becomes $T = HW/P^2$ tokens, each linearly projected from $P^2 C$ pixels to $d$, plus positional embeddings (2-D, or RoPE variants). Patch size is the resolution/compute dial: halving $P$ quadruples tokens — attention cost × 16.

def patchify(img, P):                 # img: (H, W, C) -> (T, P²·C)
    H, W, C = img.shape
    gh, gw = H // P, W // P
    p = img[:gh*P, :gw*P].reshape(gh, P, gw, P, C).transpose(0, 2, 1, 3, 4)
    return p.reshape(gh * gw, P * P * C)      # then @ W_proj -> (T, d) tokens

Contrastive pretraining. CLIP trains image and text encoders so matched pairs score high among a batch of $B$ distractors — symmetric InfoNCE with temperature $\tau$:

$$\mathcal{L} = -\tfrac{1}{2}\Big[\log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ij}/\tau}} + \log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ji}/\tau}}\Big]$$

The softmax couples every pair to the whole batch — quality depends on huge batches. SigLIP replaces it with independent per-pair sigmoids ($-\log\sigma(z_{ij}\,s_{ij})$, $z$ = ±1 for match/mismatch) — no global normalization, so it trains well at smaller batches and shards trivially. Sound familiar? It's the same logaddexp-stable sigmoid loss as Bradley–Terry in Chapter 4.

Connecting to the LLM — the design space from your own r1 session, compressed:

ConnectorMechanismTrade-off
MLP projector (LLaVA-style)encoder tokens → linear/MLP → LLM token spacesimple, strong; image tokens consume context budget
Cross-attention (Flamingo)LLM layers attend to vision tokens via inserted x-attncontext-free scaling with image count; more surgery, weaker fusion

Resolution reality: a fixed 224px encoder is legally blind for documents — hence tiling (sub-crops + thumbnail) or native-resolution (NaViT-style) inputs, at hundreds-to-thousands of tokens per image. That token budget is the same sequence-length economics as everything else in this chapter — which is the sentence that ties your whole reading room together.

traps & probe fodder
  • Patchify reshape: same trap family as the MHA head split — reshape(gh, P, gw, P, C) then transpose; a wrong order scrambles patches silently.
  • CLIP's temperature is learned (initialized ~0.07) and it matters — say why (calibrates the hardness of the softmax over the batch).
  • Contrastive features are bag-of-concepts: great init for semantics, weak for OCR/counting/geometry — the exact gap your capability roadmap (r4) exists to close.
Probe: CLIP-init encoder vs training vision from scratch inside the LLM — argue both at frontier scale
CLIP-init: semantic prior for free, converges fast, but ceilings — alt-text supervision biases toward nameable objects, fixed low resolution, and the encoder saturates while the LLM keeps scaling. From-scratch native patches: no ceiling, one architecture, native resolution — but needs far more paired/interleaved data and compute to match the contrastive prior. Frontier answer: hybrids and staged training (init from contrastive, then unfreeze and co-train at scale, raising resolution late), converging toward native as data and compute grow. Anchor with public exemplars: Flamingo/PaLI (frozen-ish), LLaVA (projector), Fuyu (native), Gemini-class (natively multimodal from the start).
