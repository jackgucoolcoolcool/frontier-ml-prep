§1.0 — One mental model: Generate → Verify → Update

Every self-improvement scheme is one loop with three slots:

$$\text{Generate}(\pi_\theta)\;\to\;\text{Verify}(V)\;\to\;\text{Update}(\theta'\leftarrow\theta)$$
  • Generate: the model (or an agent built from it) produces something — captions, rationales, trajectories, crawl decisions, judgments, synthetic images.
  • Verify: something decides what survives — programmatic checker, cross-modal consistency, judge model, environment reward, human audit, downstream-loss delta.
  • Update: survivors change the model — pretraining data, SFT data, preference pairs, RL reward, distillation targets, or a changed data-acquisition policy.
Key idea: the whole design space is what you generate, who verifies it, and where the update lands. The binding constraint is verifier quality — self-improvement is exactly as trustworthy as its weakest verifier. The loop works because of the generator–verifier gap: checking is usually easier than producing, and the loop mines that gap. A closed loop with no external verifier only redistributes competence; tools, environments, fresh web data and humans are the entropy sources.

Three timescales for closing the loop: inference-time (self-consistency, critique-and-revise, best-of-n — no weight update), post-training-time (rejection sampling, iterative DPO, RLVR — days), pretraining-time (this model curates/relabels/synthesizes the corpus for the next generation — months, biggest compounding; Part III lives here).

§1.1 — Vision stage (encoder & perception)

  • SSL objectives are self-improvement in miniature. DINO/v2/v3: an EMA teacher (the model's own slow average) generates targets for the student — Generate = teacher features, Verify = architectural anti-collapse (centering/sharpening), Update = distillation. JEPA predicts its own latents; MAE reconstructs its own masked input. No labels ever enter.
  • Model-in-the-loop annotation engines. SAM's data engine is the canonical cite: assisted-manual → semi-auto → fully-auto rounds, model retrained each round → 1.1B masks. Same pattern for grounding boxes, OCR pseudo-labels, depth/pose from specialist teachers.
  • Recaptioning flywheels. Alt-text is garbage → current VLM rewrites captions → next model trains on them (DALL·E 3 recaptioner, VeCLIP, CapsFusion). Learned lesson: fuse synthetic + raw captions — pure synthetic loses alt-text's proper nouns/world knowledge and collapses caption style.
  • Synthetic imagery with programmatic ground truth. Rendered charts/tables/documents/UIs/geometry: the rendering program is the label — infinite, perfectly verifiable supervision. T2I models fill tail concepts; cycle-consistency (caption the generated image vs the prompt) filters junk.
  • Encoder consolidation by distillation. Agglomerative distillation of CLIP+DINO+SAM into one backbone (AM-RADIO); distilling your own larger encoder down (DINOv3 pipeline). The family digests its own zoo.

§1.2 — Pretraining stage

  • Model-based filtering. Data Filtering Networks / DataComp: train a model whose job is picking data for the next model. DFN's counterintuitive result: the best filter comes from a small verified-clean training set, not the biggest model — filtering ability ≠ general capability.
  • Learnability / influence scoring. RHO-loss (keep points the current model gets wrong but a clean reference gets right — drops both the already-known and the unlearnable), MATES, TRAK/datamodel influence approximations.
  • Mixture & curriculum optimization. DoReMi (proxy + group-DRO domain weights), RegMix (regress small-run mixtures → extrapolate), and the scaling-law lens: fit per-domain loss curves at small scale, optimize the mix at target scale — the optimal image:text:interleaved ratio is itself a scaling-law object (Apple-NMM-style analysis). Quality annealing: hold the best curated data for the final LR-decay phase.
  • Generational self-distillation. Checkpoint N filters/relabels/synthesizes the corpus for checkpoint N+1; weak-to-strong results say the loop doesn't obviously cap at teacher level.
  • Synthetic interleaved documents: model-authored textbook-style pages around real images, OCR-enriched docs, chart-with-derivation pages.
The two curation equations to write on a whiteboard. RHO-loss selection — keep points that are not yet learned (high current loss) but learnable (low loss for a clean reference model): $$x^\star \;=\; \arg\max_{x\in B}\;\big[\,\ell_\theta(x)\;-\;\ell_{\text{ref}}(x)\,\big]$$ High $\ell_\theta$, low $\ell_{\text{ref}}$ → worth learning. High both → unlearnable noise, dropped. Low $\ell_\theta$ → already known, dropped. DoReMi domain weights — a group-DRO minimax on excess loss with a proxy model, then reused for the big run: $$\alpha^\star \;=\; \arg\max_{\alpha\in\Delta}\;\min_\theta\;\sum_d \alpha_d\,\big[\ell_{\theta,d}-\ell_{\text{ref},d}\big]$$ Both share one idea: a reference model turns raw loss into "learnability," separating hard-but-valuable from hard-because-garbage.

The mixture as a scaling-law object. Fit per-domain loss curves at small scale, $$L_d(N, D_d) \;=\; E_d + A_d\,N^{-\alpha_d} + B_d\,D_d^{-\beta_d},$$ then allocate the token budget so marginal returns equalize across domains: $\partial L/\partial D_d = \lambda\ \ \forall d$. Because the exponents $\beta_d$ (and irreducible terms $E_d$) differ per domain, the optimal mixture is scale-dependent — which is exactly why per-category value curves cross in Fig. 6 and why P1's proxy rankings can't be trusted blindly.

§1.3 — Post-training stage

  • Rejection-sampling / self-training (the workhorse): STaR / ReST / ReSTEM — sample k, keep verified-correct, fine-tune, iterate; plus STaR's rationalization trick (show the answer, ask for the reasoning) when nothing verifies.
  • RLVR — the strongest current loop because the verifier is programmatic: visual math, chart/table QA checked against source data, OCR exact-match, counting vs detector, screenshot-to-code with render-and-compare (render the generated code, pixel/DOM-diff vs target — a purely visual verifier), GUI-agent tasks with environment-state success checks.
  • RLAIF / self-rewarding: model judges outputs → preference pairs → iterative DPO (Self-Rewarding LMs); constitutional critique-and-revise manufactures its own SFT data; RLAIF-V splits captions into atomic claims and verifies each.
  • Hallucination-targeted loops: construct (hallucinated, corrected) pairs → DPO (POVID, HA-DPO); reward = fraction of caption atoms confirmed by detector/OCR.
  • Self-consistency as pseudo-label when no verifier exists: majority vote across samples becomes the target.
  • Agentic post-training: web/GUI/tool rollouts in environments; keep successes → SFT → RL on environment reward. The environment is a free verifier.
The three post-training loop equations. ReSTEM is EM on the verifier: E-step samples and keeps verified outputs, M-step fits them — $$\theta_{t+1} \;=\; \arg\max_\theta\; \mathbb{E}_{x\sim\mathcal{D},\;y\sim\pi_{\theta_t}(\cdot\mid x)}\Big[\,\mathbb{1}[V(x,y)=1]\;\log \pi_\theta(y\mid x)\Big]$$ Iterative DPO on self-generated preference pairs $(y_w,y_l)$ (from a judge, a verifier, or hallucination-vs-corrected construction): $$\mathcal{L}_{\text{DPO}} \;=\; -\log\sigma\!\Big(\beta\log\tfrac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} \;-\; \beta\log\tfrac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\Big)$$ RLVR — maximize programmatic reward with a KL leash (the leash is what P4/P9-style collapse and hacking look like when it's missing): $$\max_\theta\;\mathbb{E}_{y\sim\pi_\theta}\big[R_{\text{verify}}(x,y)\big] \;-\; \beta\,\mathrm{KL}\big(\pi_\theta \,\Vert\, \pi_{\text{ref}}\big)$$ Rejection sampling amortizes search into weights: train on best-of-$n$, deploy at $n{=}1$.

How RLVR actually runs: GRPO. Sample a group of $G$ rollouts per prompt, score with the programmatic verifier, and use the group-relative advantage — no value network needed: $$A_i \;=\; \frac{r_i - \mathrm{mean}(r_{1:G})}{\mathrm{std}(r_{1:G})}, \qquad \mathcal{L}_{\text{GRPO}} \;=\; -\frac{1}{G}\sum_{i=1}^{G} \min\!\big(\rho_i A_i,\; \mathrm{clip}(\rho_i, 1\!-\!\epsilon, 1\!+\!\epsilon)\,A_i\big) \;+\; \beta\,\mathrm{KL}$$ ($\rho_i$ = importance ratio vs the old policy.) Two doer notes: groups where all rollouts pass or all fail contribute zero gradient — so task-difficulty curation (keeping pass-rate near 50%) is itself a data-engine problem; and the std-normalization makes reward scale irrelevant but reward blind spots fatal — GRPO amplifies whatever the verifier can't see.

§1.6 — Deep insights: the theory under the plumbing

  1. Selection vs. gradient — the two arms are not equal. Filtering, best-of-n, rejection sampling are selection operators: they reweight the support of the current distribution but cannot create new modes. And selection is KL-bounded: $$\mathrm{KL}\big(\pi_{\text{BoN}}\,\Vert\,\pi_{\text{base}}\big)\;\le\;\log n-\tfrac{n-1}{n}\;\;\text{nats}\;\;(\approx 2.5\text{ at }n{=}32;\text{ doubling }n\text{ buys only }\ln 2\approx 0.69\text{ more})$$ The escape hatch is iterate-and-distill (ReSTEM, iterative DPO): each round distills the selected distribution into the weights, re-centering the reference, then selects again — the KL budget compounds across rounds, and gradient updates generalize selected behaviors into compositions selection alone can't reach. This is the deep reason "amplify → distill → repeat" is the master recipe and one-shot best-of-1024 is not.
  2. Entropy accounting. Every loop converts diversity into capability. Income: fresh web data, tools, environments, humans. Expense: every selection step. Income < expense → collapse (model collapse is the bankruptcy case). The anchor ratio works because it lower-bounds income. Doer corollary: track corpus/policy entropy like a KPI, not as a post-mortem.
  3. Verifier decay is dynamical, not an event. Under optimization pressure every learned verifier slides down the Fig 1b hierarchy toward "heuristic" — Goodhart is a rate, not a threshold. Consequence: refresh cadence beats initial quality; a mediocre judge refreshed every cycle outlives a brilliant frozen one. (P2/P9/P15 are the same theorem observed three times.)
  4. Elicitation vs. creation. Post-training self-improvement mostly surfaces what pretraining latently contains; the pass@k vs pass@1 gap is the elicitable headroom. Doer rule: measure pass@1024 before green-lighting an RL loop — flat pass@k means no reward will help; go fix the pretraining data instead. Corollary: data-side loops raise the ceiling; post-training loops raise the floor toward it.
  5. Captions are the label space. Recaptioning isn't "cleaning" — it decides which visual features become linearly accessible: dense spatial captions teach layout, entity-rich alt-text teaches world-knowledge grounding, OCR-injection teaches reading. "What you caption is what you get": the mixture over caption styles is a first-class hyperparameter, not a footnote.
  6. Data outlives architecture. A corpus improvement pays into every future model generation and survives architecture migrations; a post-training trick pays once. That asymmetry — not fashion — is why data engines get the senior headcount, and why the slowest loop (pretraining-timescale) has the highest NPV.
  7. The binding rate is eval latency. The cycle time of Generate → Verify → Update is dominated by "how long until you can trust a measurement," not by generation. Halving eval latency doubles the improvement rate of the whole engine — which is why probe suites and scaling ladders (P1) are the crown jewels, and why the org that measures fastest wins.

§2 — Data-side self-improvement: six verbs

Definition: the model improves the corpus (and the corpus-building policy) rather than its own weights directly. Ordered by how much the model creates vs. selects:

VerbWhatKey mechanismsSharp edge
1. FILTERscore & selectdistilled quality scorers (DFN pattern: big model labels ~1M → train 100M scorer → run on 10B), CLIP-align, learnability (RHO), safety gatesa filter is a model with a ceiling; its systematic false-negatives silently delete whole capability categories
2. RELABELenrich what you keepdense recaptioning, OCR injection, grounding, table→markdown, chart→data; caption fusion not replacementsynthetic captions are style-collapsed and entity-poor; alt-text carries proper nouns — fuse (CapsFusion)

4. ACQUIREactively collecteval-gap → targeted crawls; ensemble-disagreement seeking; a bandit/RL problem over the web (action = crawl/render choice, reward = realized data value)Part III entirely

6. RECYCLEdeployment exhaustthumbs/regenerations/edits → preference pairs; failure miningconsent/privacy; heavy selection bias
Cross-cutting machinery: dedup (MinHash + SemDeDup — also a quality and memorization intervention), decontamination against every reported eval, the anchor ratio (cap the model-touched fraction; real data is the entropy source), and the value model $$\text{value}(x)\;\approx\;\underbrace{q(x)}_{\text{quality}}\times\underbrace{\ell(x)}_{\text{learnability}}\times\underbrace{d(x\,|\,\mathcal{D})}_{\text{marginal diversity}}\times\underbrace{v(x)}_{\text{verifiability}}$$ Selection on any single factor fails: quality-only → homogeneous; learnability-only → noise-seeking; diversity-only → junk. The meta-loop: eval diagnostics → acquisition/synthesis targets → curation → proxy-pretrain validation → mixture update. Data-side self-improvement = making this loop fast and trustworthy.
Three more whiteboard tools.

1 — Targeted acquisition is importance resampling (DSIR). "Crawl what fixes the eval gap" formalized: estimate target and raw densities with cheap features (hashed n-grams / embedding bins) and resample the pool with $$w(x) \;\propto\; \frac{\hat p_{\text{target}}(x)}{\hat p_{\text{raw}}(x)}$$ where $\hat p_{\text{target}}$ is fit on exemplars of the weak capability (e.g., infographic-style pages). Eval-gap-driven crawling is DSIR with the target density defined by your failure analysis.

2 — Cycle-consistency as a one-line label filter. Within a batch of $B$ images, keep synthetic caption $c_i$ only if it retrieves its own image: $$\mathbb{1}\Big[\arg\max_{j\in[B]} \mathrm{sim}(c_i, x_j) = i\Big]$$ Catches captions that describe an image like this rather than this image — the signature failure of a recaptioner running on autopilot. Raise $B$ to raise strictness.

3 — Diversity accounting. Cluster the intake embedding space; track $H = -\sum_k p_k \log p_k$ and report effective clusters $e^{H}$ (the perplexity of the cluster distribution — same math as vocabulary perplexity). This is the y-axis of Fig. 5 and the metric behind the P4 alarm; entropy in nats, naturally.

§3 — Project: Self-Improving Multimodal Web Scraper (Gemini-setting mock)

Framing: hypothetical composite for mock-interview practice / "design a data engine" answers — rehearse the narration and the pushback, don't claim it as work history.

§3.1 Elevator pitch (STAR, 45s)

Situation: pretraining wanted more high-value multimodal web data — interleaved image-text docs, charts, documents, UI screenshots — but bulk-crawl + static heuristic filters waste most crawl/render/storage cost on boilerplate and freeze one notion of quality. Task: a closed-loop data engine — a VLM-guided scraper deciding where to crawl, what to render/extract, how to label, and updating its own acquisition policy and quality scorer from measured downstream data value. Action: five subsystems, three shipped policy iterations. Result (illustrative, memorize as practice numbers): ~4× useful-tokens-per-crawl-dollar vs baseline; at matched token budget on proxy pretrains: +6 ChartQA, +4 DocVQA, +3 InfographicVQA, neutral text-only; distilled scorer retired two legacy heuristic filters.

§3.2 System design

The acquisition objective (one equation that encodes three problem-fixes). Each candidate URL/domain $u$ is prioritized as $$\text{priority}(u) \;=\; \underbrace{\hat V_\phi(u)}_{\text{multi-signal value}} \;+\; \lambda_{\text{div}}\,\underbrace{\Delta\mathrm{cov}(u \mid \mathcal{B})}_{\text{submodular diversity bonus}} \;+\; \lambda_{\text{expl}}\,\underbrace{\sqrt{\tfrac{\log t}{n_{d(u)}}}}_{\text{UCB exploration}}$$ $$\text{subject to}\quad \mathrm{KL}\big(p_t \,\Vert\, p_{t-1}\big) \;\le\; \epsilon \;\;\text{(per-iteration intake-distribution shift cap)}$$ $\hat V_\phi$ = distilled scorer + learnability + type priors (kept separate, combined here); the diversity bonus makes the objective a set function (fixes P4 collapse); the UCB term is the 15% exploration budget in disguise; the KL cap on the intake distribution rate-limits how fast the policy can chase scorer blind spots (fixes P9 hacking). Same structure as the RLVR objective above — that's not a coincidence, it's the same Goodhart problem.

Ops reality: tiered budgets (illustrative numbers to memorize)

TierFraction of URLsWhat happensUnit cost (rel.)Gate
T0 static parse100%HTML fetch, DOM stats, cheap fingerprint, template hash1×—
T1 light render~20%headless render, screenshot, banner removal, layout check~30×T0 features → policy predicts value
T2 full extract + label~5%interleaved doc build, fused recaption, OCR cross-check, grounding~200×T1 screenshot passes fidelity checks
T3 big-judge audit~0.5% samplefrontier-model quality judgment → scorer training data + drift monitoring~2000×stratified sample of T2 output

The economics only work because each tier's model is trained/refreshed from the tier above it (T3 judgments → T2 scorer → T1 value predictor → T0 priors) — a distillation cascade down the cost curve. That cascade is the engine's actual product; the corpus is a by-product.

The self-improvement claim, precisely: the loop improves the data engine (policy + scorer + labeler) → better corpus → better model → better judgments powering the engine. Model-side training itself stays standard.

§3.3 The ten real problems (the meat)

P1 — Credit assignment: you can't wait for a frontier pretrain to know if data helped▶
True data value is defined by a run you can't afford per batch. Tried: (a) CLIP-score filtering — plateaued, stock-photo aesthetic bias, anti-selected documents/charts; (b) learnability-only (reference-model excess loss) — noise-seeking: garbled OCR pages look "hard but learnable". Landed on a scaling ladder: proxy pretrains at 3 sizes, per-capability eval suites, trust a batch only if its ranking transfers across scales. Found rank corr ≈ 0.7 overall but much worse for OCR-heavy data (value only appears at scale) → dedicated OCR probe suite. Lesson: data value is scale-dependent; validate rank transfer, not one score — a scaling-law problem (fit per-category value curves, distrust curves that cross).
P2 — The distilled scorer learned style, not quality▶
Top decile filled with SEO listicles mimicking good-content structure. Diagnosis: judge self-preference/style bias, amplified by distillation. Fixes: human-audited golden set (refreshed monthly) as the scorer's acceptance test; adversarial probes (SEO farms, MT content, template mills); ensemble with judge-independent signals (OCR density, link-graph authority). Lesson: a distilled scorer inherits its teacher's biases compressed and amplified — you need ground truth that never touched the teacher.
P3 — Recaption hallucination poisoning▶
Recaptioner asserted wrong counts, misread scene text, invented attributes on a few % of images — at pretrain scale, a curriculum in confident hallucination. Fixes: verifier stack (OCR exact-match for quoted text, open-vocab detector for counted/named objects, batch cycle-consistency retrieval); uncertainty-aware phrasing for unverifiable claims; ~40% raw alt-text kept via caption fusion as entity/entropy anchor. Post-fix, proxies improved on POPE/CHAIR-style evals instead of regressing. Lesson: synthetic label errors aren't random noise — they're systematically fluent, so learned preferentially.
P4 — Feedback-loop distribution collapse▶
By iteration 3, intake concentrated on scorer-favorite content types; embedding-cluster entropy of weekly intake fell ~20%; long-tail domains vanished. Nothing "failed" item-wise — the portfolio degraded. Fixes: fixed 15% exploration budget (stratified random + frontier domains), per-cluster caps, submodular-style marginal-diversity bonus, coverage dashboards with alarms as launch criteria. Lesson: data value is a set function; item-score optimization is the wrong objective. Same math as RLHF entropy collapse, same fix shape (explicit entropy/KL term).
P5 — Templated near-duplicates▶
E-commerce/news templates dominated; embedding dedup missed them (same template, different product) or, tightened, deleted legit similar content — charts of different data look alike in embedding space. Fix: two-stage — DOM-structure MinHash for template detection + per-domain caps, then embedding dedup only within a content type with type-specific thresholds (documents tight, charts loose). Lesson: one global similarity threshold is a category error in multimodal corpora.
P6 — Rendering fidelity and cost▶
Lazy-load images missing, cookie banners eating 30% of pixels, JS timeouts, anti-bot walls. Fixes: scroll-and-settle with network-idle detection; banner/overlay classifier + DOM removal pre-screenshot; tiered render budgets gated by predicted value; robots.txt + politeness as hard constraints (blocked-crawl signals become features, not fights). Lesson: the boring rendering layer sets data quality as much as any ML piece, and garbage screenshots are invisible in aggregate metrics — institutionalize weekly "look at 100 random samples" reviews.
P7 — Eval contamination, adversarially concentrated▶
A value-seeking policy gravitates toward benchmark-like content (bench figures circulate; bench-like pages score high on every value signal — that's why they became benchmarks). Decontam (n-gram + perceptual-hash + embedding match vs all eval suites, canaries) caught a small rate concentrated exactly in the highest-value categories. Fix: decontam as mandatory pipeline stage, quarantine logs, eval versioning, contamination rates reported next to every claimed win. Lesson: the better your engine, the more contamination-seeking it is.
P8 — Safety/licensing filters vs recall▶
CSAM/NSFW/PII at maximal recall (non-negotiable) collateral-damaged medical imagery, art, documents with incidental faces; license extraction added more recall loss. Fixes: tiered filtering with human-review lane for the gray zone; end-to-end provenance metadata (takedowns/audits executable later); explicit accounting of which capability categories the safety stack suppresses. Lesson: filters are part of the data distribution — "mysteriously bad at X" is often "the filter ate X."
P9 — The acquisition policy reward-hacked the scorer▶
The bandit found a blind spot: equation-dense pages scored high (scorer associated math density with quality) but many were OCR-garbled forum scrapes — intake flooded with them. Classic Goodhart, isomorphic to RLHF reward hacking. Fixes: asynchronous adversarial cadence (scorer refreshed with fresh big-model judgments after every policy update — the policy optimizes a moving, repaired target); KL-style cap on per-iteration intake-distribution shift; human spot-checks of each new policy's top-decile picks before ingestion. Lesson: any learned value model under optimization pressure gets hacked; schedule verifier refresh against optimizer updates and rate-limit distribution shift.
P10 — Attribution: which change caused the win?▶
Mixture update + scorer refresh + new chart extractor shipped together; ChartQA +5; which to double down on? Post-hoc untangling ≈ impossible. Fixes: one-change-per-proxy-run discipline (proxies are cheap controlled experiments — fixed seeds and data order); interleaved A/B pretrains at matched token counts for headline claims; TRAK/datamodel influence approximations for triage only, never claims. Lesson: a data engine without experimental discipline produces unreproducible improvements — data changes deserve architecture-change rigor.

§3.6 Crawler self-improvement — the render-vs-extraction critic

The key idea: every page ships its own ground truth. The rendered screenshot is what a human sees; the extracted interleaved doc is what the model will eat. Any divergence is a pipeline bug — and detecting it requires no labels, because the page supplies both views. This is render-and-compare turned inward: instead of verifying model outputs against a rendering, you verify the pipeline's output against the rendering. Same Generate → Verify → Update loop, applied to infrastructure, with a level-2 (cross-modal consistency) verifier from Fig. 1b.

The discrepancy taxonomy (structured critic output: code + severity + bbox ↔ doc-span)

CodeFailureTypical cause
MISSINGvisible in screenshot, absent from doclazy-load images, JS-rendered text, canvas-drawn charts
PHANTOMin doc, invisible on pagenav/boilerplate leakage, cookie banners, hidden SEO text
ORDERwrong reading ordermulti-column layouts, caption attached to the wrong image
FIDELITYpresent but corruptedmangled tables, OCR errors, wrong chart→data extraction
COVERAGEpage truncatedinfinite scroll, pagination, tabs/accordions
SEMANTICimage↔text misalignedalt-text describes a different image, fused caption drifted

Stage attribution — which component is guilty? Three cheap diffs localize the fault before any fix is attempted: DOM-declared resources vs what actually painted (→ rendering); DOM text vs doc text (→ extraction); screenshot vs synthetic captions (→ labeling). Without this, every report starts a cross-team argument; with it, reports route themselves.

Loop A — improve the crawler (the component)

  1. Template-level rule patching. Cluster reports by DOM-template hash; a code-gen model writes/patches per-template extraction adapters; a golden regression set (screenshot, verified-extraction) gates every patch. Highest-frequency templates first — blast-radius-ordered triage.
  2. Screenshot-grounded extractor. The critic doesn't just flag — it proposes the corrected doc from the screenshot. Distill those corrections into the extraction model. End state: extraction stops being DOM heuristics audited by a VLM and becomes a VLM that reads the page image with the DOM as a hint, trained almost entirely by cycle-consistency with its own pipeline.
  3. Render-policy bandit. Rendering-attributed discrepancies become the reward for the render controller (scroll/settle, wait budgets, interaction probes), optimized per critic-score-per-render-dollar.
  4. Acquisition feature. Per-domain extraction fixability feeds the crawl policy: don't keep buying pages you can't correctly extract.

Loop B — improve the data (the product)

  1. Quarantine & repair. Severity-weighted: re-render with a better policy, re-extract with the patched adapter, or accept the critic's corrected doc directly (with the P15 caveat).
  2. Blast-radius backfill. Every doc carries lineage (extractor version, template hash, render config). When a systematic bug surfaces, query the corpus for affected docs and reprocess retroactively. Lineage is what makes pipeline bugs reversible — without it, every bug is permanent corpus damage.
  3. The taxonomy becomes the pipeline's eval. Confirmed failures graduate into an adversarial golden suite every extractor release must pass; the per-template/domain/version discrepancy histogram is the pipeline's dashboard.

The new problems this creates (P11–P15)

P11 — The shared blind spot: screenshot and doc agree, and both are wrong▶
If the render is broken (lazy-load never fired), the missing content is absent from both views — the critic sees consistency, not truth. Guards: multi-render disagreement probes (two renders under different policies; divergence flags a rendering issue) and DOM-declared-resource checks (an <img> with a src that never painted is a smoking gun no screenshot comparison can see). Lesson: cross-modal consistency verifies agreement, not ground truth — you need at least one signal that bypasses the shared failure path.
P12 — Critic cost at corpus scale▶
Frontier-critic on every page and the economics die. Same answer as §3.2: a distillation cascade — the big critic runs on stratified samples and trains a cheap discrepancy predictor that runs on everything; sampling then biases toward predicted-error and new templates. The T3→T0 cost cascade gains a parallel critic column.
P13 — Critic false positives on interactive content▶
The critic flags "missing" content that is reachable but not visible — behind tabs, accordions, hover states. Fixes: a visible/reachable distinction in the taxonomy, and measuring critic precision on human-audited goldens before wiring it to automation. A noisy critic auto-patching extraction rules is a self-inflicted DDoS on your own pipeline.
P14 — Reading order is sometimes genuinely ambiguous▶
Card grids and dashboards have no canonical linear order. Don't force one: mark ambiguity explicitly and train downstream with order-tolerant objectives or layout tokens, rather than punishing the extractor for an unanswerable question. Lesson: a verifier must know which questions have no right answer, or it manufactures noise.
P15 — Goodhart, round three: the extractor inherits the critic's blind spots▶
An extractor distilled from critic corrections learns the critic's biases — the same shape as P2 (scorer style bias) and P9 (policy hacking the scorer). Same fix shape: refresh the critic from the newest frontier model each generation, and keep a human-audited golden set that never touched any critic as the acceptance test. By round three the pattern is the thesis: every learned verifier under optimization pressure needs an unoptimized anchor.

Why this framing wins: it upgrades the scraper from "a bandit that picks URLs" to a self-verifying system in which the page itself is the supervisor — and it closes a second, deeper flywheel: better VLM → sharper critic → better extractor → cleaner interleaved data → better VLM. The data engine bootstraps its own perception.

§3.7 Field notes — details only doers know

The texture that separates "I read about data engines" from "I ran one." Grouped by where the scar tissue is.

Measurement discipline

  • Paired seeds or it didn't happen. At 1B proxy scale, most public VLM benchmarks carry 1–3 points of seed noise. A "+2 win" that evaporated under paired-seed reruns once killed a quarter's roadmap. Every proxy A/B: same seed, same data order, only the candidate batch swapped. Error bars on everything, or the meeting is fiction.
  • Early-signal probes beat benchmarks at proxy scale. A 2k-item exact-match OCR probe, an entity-cloze set, and per-domain perplexity slices detect data effects ChartQA (noisy, 2.5k items) cannot see at 1B. Maintain an explicit probe→benchmark mapping validated on the scaling ladder — probes are the instrument panel; benchmarks are the quarterly report.
  • The insertion protocol changes the answer. The same candidate batch measured mixed into pretraining vs inserted in the annealing slot gives different — sometimes opposite-sign — value estimates. Standardize one protocol (we fixed a 20%-of-anneal insertion slot) or no two measurements are comparable.

The ledger

  • The mixture you specify is not the mixture you train on. Dedup once deleted 80% of one domain, silently re-weighting the whole mixture downstream of the config file. Only post-filter token accounting — the data ledger — is truth. Recompute mixture weights after every pipeline change; diff the ledger, not the config.
  • Watch the score histogram, not just the evals. A thresholded scorer puts the most ambiguous pages exactly at the cut, so small scorer drift moves millions of pages across it. A silent scorer retrain once dropped intake volume 30% for a week before anyone noticed — downstream evals wouldn't have shown it for a month. Alarm on intake volume per content type and score-distribution drift: $D_{\mathrm{KS}} = \sup_s \lvert F_t(s) - F_{t-1}(s)\rvert$ vs last week's score CDF.

The render farm

  • The p99 kills you, not the median. Median render 1.2s; p99 45s — JS-heavy pages, crypto-miner scripts pegging CPU, one SVG map page with 300k DOM nodes stalling extraction for minutes. Survival kit: recycle browser processes every N pages (headless Chrome leaks), hard DOM-node caps, a kill-list for known CPU traps, per-page compute budgets enforced by timeout tiers.
  • Keep canary pages. A per-domain set of known-stable pages, re-rendered daily, is the only reliable way to distinguish "the site redesigned" from "our IP range got blocked." Without canaries both look like extraction-failure spikes and you debug the wrong layer for a day.
  • The web is nonstationary — as a monitoring requirement, not a philosophy. A major CMS platform update once shifted the template distribution of a double-digit share of the crawl overnight; extraction failures spiked while every service was "healthy." Template-distribution drift alarms belong next to loss curves.

Data content traps

  • Alt-text is secretly load-bearing for entities. A 100%-synthetic-caption slice improved VQA but cratered proper-noun retrieval (landmarks, products, people) — invisible in aggregate, caught only by the entity-cloze probe. The ~40% raw-caption fusion ratio wasn't taste; it came from a 0/20/40/60/80 sweep against that probe.
  • The axis-label trap. Chart→data extraction fails silently on log axes and truncated axes — extracted numbers are fluent and wrong, teaching wrong magnitudes at scale. Rule: only keep chart QA pairs whose numbers cross-check against the page text or an underlying data table. Fluent-and-wrong is worse than absent (same theorem as P3).
  • Paraphrase contamination rides the scrape date. One "improvement" traced to crawl recency: newer pages discussed a benchmark (paraphrased items, worked solutions in blog posts). N-gram decontam missed it entirely; embedding decontam caught half. Date-stratified ablations are part of the decontamination kit, not an optional extra.

Humans and constraints

  • Reviewer-minutes are a budget line. Better safety filters surface more borderline cases, so the gray-zone human-review queue grows superlinearly as filters improve. Plan reviewer-minutes per million pages as a first-class resource or the pipeline stalls on its human lane while every machine dashboard shows green.
  • Politeness-aware optimization. Crawl-rate limits mean the bandit's best arms are drip-fed — a high-value domain at 1 req/s is worth less than its score implies. If the acquisition optimizer doesn't see politeness constraints inside the value estimate, it spends its budget standing in queues.

Self-test drills

State the universal self-improvement loop and its binding constraint.▶
Generate → Verify → Update, at three timescales (inference / post-training / pretraining). Binding constraint: verifier quality — the loop is exactly as trustworthy as its weakest verifier; it works by mining the generator–verifier gap. A closed loop with no external verifier only redistributes competence.
Rank the verifier hierarchy for multimodal data.▶
Programmatic (render-and-compare, OCR exact-match, executable checks) > cross-modal consistency (caption retrieves its image, detector confirms objects) > model judge (RLAIF, self-reward) > heuristic (CLIP score, length). Push every task as high up the hierarchy as it can go; rendered-with-source synthetic data is highest-leverage precisely because supervision is programmatic and infinite.
Why does caption fusion beat caption replacement?▶
Synthetic captions are visually thorough but style-collapsed and entity-poor; alt-text is noisy but carries proper nouns and world knowledge. Replacing loses entities and narrows the text distribution (a mini model-collapse); fusing (CapsFusion) keeps both. Also serves as an entropy anchor against recaption hallucination (P3).
Your scraper's intake diversity is dropping across iterations. Name the failure and three fixes.▶
Feedback-loop distribution collapse (P4): selection pressure on item scores homogenizes the portfolio. Fixes: fixed exploration budget (ε/stratified), per-cluster intake caps or submodular diversity bonus (value is a set function), coverage/entropy dashboards with alarms. Same math as RLHF entropy collapse — add an explicit entropy/KL term.
How would you know a candidate data batch actually helps the frontier model, without training it?▶
You can't directly — build a scaling ladder: proxy pretrains at several sizes with fixed seeds/data order and per-capability probes; trust the batch only if its ranking transfers across scales; treat per-category value as a scaling-law object and distrust categories whose curves cross (OCR-heavy data pays off only at scale). Keep one-change-per-run discipline so attribution survives (P1 + P10).
When should you refuse to start an RL self-improvement loop?▶
When pass@k is flat: post-training loops mostly elicit latent pretraining capability, and the pass@k vs pass@1 gap is the elicitable headroom (§1.6). If pass@1024 shows nothing, no reward signal can select what isn't there — the fix is pretraining data (raise the ceiling), not RL (raise the floor toward the ceiling). Also refuse when there's no verifier above level-3 for the task and no plan for judge refresh: a frozen learned verifier under optimization pressure decays into a heuristic (Goodhart is a rate, not an event).
Why does iterate-and-distill beat one-shot best-of-n?▶
Best-of-n is a selection operator: KL-bounded at $\log n - \frac{n-1}{n}$ nats (~2.5 at n=32, +0.69 per doubling) and only reweights existing modes. Iterate-and-distill (ReSTEM, iterative DPO) distills each round's selected distribution into the weights — re-centering the reference — so the KL budget compounds across rounds, and gradient generalization composes selected behaviors into new ones. Amplify → distill → repeat converts a bounded optimizer into an unbounded one; that's also why it needs the entropy accounting of §1.6 (each round spends diversity).
Your extractor and your screenshot agree perfectly. Are you done?▶
No — that's P11, the shared blind spot. Screenshot-vs-doc comparison verifies agreement, not ground truth: if the render itself failed (lazy-load never fired), both views are missing the same content and the critic sees consistency. You need at least one signal that bypasses the shared failure path: multi-render disagreement probes (two render policies must agree) and DOM-declared-resource checks (a declared <img> that never painted). General principle: any consistency-based verifier has a common-mode failure; audit for it explicitly (§3.6).
Argue both sides: can a model self-improve past its teacher?▶
For: the generator–verifier gap (verification easier than generation) lets a model curate a curriculum better than its own outputs; weak-to-strong shows student > supervisor; tools/environments inject external truth, so the loop isn't informationally closed. Against: with only a self-judge, biases amplify (self-preference, style collapse) and the ceiling is the verifier, not the generator; model collapse under recursive synthetic training. Commit: yes, iff at least one verifier injects information the generator lacks (program, environment, fresh data, humans).

Test-time compute: deliberate reasoning vs best-of-N

Sequential self-refinement compounds — each step conditions on the previous attempt — so quality grows roughly Q(C) ≈ a + b·log C. Best-of-N only takes the max of independent draws, so its gains flatten (extreme-value scaling ≈ a + b·log log N).
